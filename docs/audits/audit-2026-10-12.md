# Deep audit, October 12, 2026

## Scope

The audit covered the `vfe3` package (about 85,000 lines in 112 files), the root entrypoints and the test suite at `main` = `6b872b4`, the merge of PR #92. The user asked for three things: candidates for improvement, configuration toggles that can or should be hardcoded, and theoretical or mathematical improvements that the theory supports and the code could implement. The theory reference was the user's `GLK_attention_v2.tex` (1,846 lines), supplied for this audit.

The active configuration is the `train_vfe3.py` launcher dictionary at this commit:
- K = 20 with two heads of 10, N = 128, batch 32, four layers;
- `gaussian_diagonal` with the linear decoder;
- `projected_predictive` with `predictive_readout = "minimal_agent"` (mean field, one sweep) and `block_mlp_mode = "prototype_agents"` (mean field);
- moment-matched predictive covariance (floor 1e-4), the exponential content chart, the causal prior;
- block_glk per-head frames with learned positional frames, AdamW everywhere;
- `amp_dtype = "bf16"`, `fp32_matmul_precision = "highest"`.

Findings already remediated in the October 9, 10 and 11 audits and logs were excluded unless an investigator showed a regression.

## Method

Six investigators ran in parallel, each on a disjoint area:

| Investigator | Area |
|---|---|
| config | `vfe3/config.py` fields, validation, `inactive_fields`, migrations; launchers, ablation and paper arms |
| theory | the manuscript against `free_energy.py`, `families/`, `inference/`, `gradients/`, `relational_scoring.py`, the minimal agent, the prototype agents and the moment-matched covariance |
| geometry | `vfe3/geometry/`, `gauge_optim.py`, `table_optim.py`, `edge_links.py`, positional frames and RoPE |
| model | the forward and backward hot path in `vfe3/model/`, `relational_scoring.py`, `kernels/`, `numerics.py` |
| training | `train.py`, `metrics.py`, `run_artifacts.py`, data, baseline, entrypoints |
| hygiene | `viz/`, `semantics/`, `posthoc/`, `paper/`, their drivers, dead code and the test suite |

A CPU torch build (2.14.1, Linux) was installed in a session scratch environment partway through. The config, geometry and model investigators ran repository code on tiny versions of the active configuration. The theory, training and hygiene investigators started before the install finished. Their evidence is code reading plus numpy or scipy reimplementations of the code's formulas, checked line by line against the source. Each finding below says which kind of evidence it rests on. The coordinator re-ran the inert-field census and the LayerNorm pushforward reproduction, and checked four further claims against the source: the stale summary key, the 2·SD noise floor, the learning-rate logging order and the bf16 inert rule. No GPU was used, and no source file was edited during the audit.

## What was verified correct

These checks found no defect and are recorded so that later audits need not repeat them.

- **Causality.** On the active configuration, perturbing token j left every earlier position's mean, covariance and logits bitwise identical. The gradient from any output at position i back to encoded beliefs at j > i was exactly zero. The same held under bf16 autocast, with three CAVI sweeps, with exact inference for both agents, with the prototype posterior covariance, the kernel readout, reference coordinates and `gaussian_full` (run).
- **Gauge covariance.** A common reference change U_i → U_i a, applied to every frame, query map and receiving map of a tiny active-configuration model in float64, changed the logits by 1.3e-15 for orthogonal a. A site action on one minimal-agent layer was covariant to 4e-14 for full covariance and to 7e-16 for diagonal covariance in the diagonal stabilizer. This confirms the composition order Ω_ij = U_i U_j⁻¹ (run). General a is covariant only up to the covariance floor (item 4).
- **Manuscript conformance.** The projected Gaussian KL (factor ½, log-determinant sign, the −r term, the direction KL(q_Q‖p_K)), the dual-coordinate theorem and its key-norm example, the Gibbs row softmax(log π − D/τ) with an unscaled prior and τ = κ√d_head, the [0, 8K] cost bound, the moment-matched kernel covariance (term for term, and checked against 2e6 Monte Carlo samples to 4.4e-4), the decoder Gibbs identity, the Rényi closed form and the exponential chart identity all match the manuscript. The minimal-agent mean field is a correct CAVI step, and its ELBO rose monotonically over eight sweeps in all four regimes tried (algebra and reimplementation).
- **Decode.** The fused and dense cross-entropies agree to 5e-7 for every decode mode and covariance source (run).
- **Training loop.** The following were traced and found correct:
  - resume exactness: the scheduler at the accepted-update count, the per-epoch window origin, the data order and the RNG state;
  - `eval_stride` accounting, which scores every transition exactly once;
  - token-weighted evaluation;
  - gradient accumulation, with no GradScaler under bf16;
  - weight-decay grouping for the live configuration;
  - split disjointness, with selection on validation only.

## Findings

Severity applies to the effect on results under the configuration where the defect is live. "Active" means it is live on the launcher at this commit.

### Defects

1. **High (opt-in, offered in the launcher).** `block_norm_covariance = "pushforward"` makes the covariance explode, and the loss can go NaN silently.
   - **Where:** `vfe3/model/block_mlp.py:232-273, 328-385`; `vfe3/model/block.py:308-311`; `vfe3/model/model.py:1176-1184`.
   - **Cause:** the delta-method pushforward through LayerNorm is valid only when the belief variance is small against s², the spread of the mean across coordinates. Its first-order term grows as Σ/s² and its radial term as (Σ/s²)². The exact LayerNorm output lies on a sphere, so its standardized covariance trace is at most K.
   - **Measured:**
     - At the launcher's initialization (mean std 0.065, Σ = 15, so Σ/s² ≈ 4e3), the pushforward trace is 7.0e6 against a Monte Carlo trace of 20.0.
     - In the model the largest per-layer covariance goes 8 → 2e7 → 3e19 → NaN by layer 3.
     - At `sigma_init = 1` the run does not raise; the loss becomes NaN.
     - With a coordinate MLP the loss stays finite while the returned covariance is NaN.
   - **History:** the October 11 validation used Σ ≈ 1e-3 s² only. The `delta_full` composite shares the cause.
   - **Evidence:** run, reproduced by the coordinator.
2. **Medium (active path).** The prototype mean-field update on the diagonal layout never flags non-finite values, at `vfe3/model/prototype_agents.py:612-631`: `failed` stays None. A NaN working covariance therefore becomes a NaN loss with no error and no float64 retry. The block and dense layouts and the minimal agent all flag failures. This is why item 1 can be silent (run).
3. **Medium-high (active).** Frame conditioning has no bound, and the operative limit is a run abort.
   - **Why nothing bounds it:** `phi_mstep_max_matrix_norm = None` leaves AdamW on `phi_embed` and `pos_phi_free` unbounded, and the chart radius of 50 is checked per factor (`vfe3/geometry/transport.py:1122`), not on the composed frame. A radius of 50 admits a condition number near 5e30 per factor.
   - **Measured:** with the real fp32 pair and `CanonicalFrameContext`, a traceless symmetric stretch with Frobenius norm 10.4 passes silently at κ₂ ≈ 1.2e6 with pair residual 3.2e-3. At norm 12.4 it raises, because the residual 0.044 exceeds the 1e-2 cap at `vfe3/contracts.py:187`.
   - **Precedent:** the seed-54 history in `docs/2026-10-04.md` shows AdamW grows such stretches.
   - **Existing option:** `project_phi_parameter_rows_` (`vfe3/gauge_optim.py:1022`) shrinks the whole vector, including rotations and the trace, which do not affect conditioning.
   - **Evidence:** run and code trace.
4. **Medium (active, theory against code).** The moment-matched floor f·tr(C_i)/K·U Uᵀ breaks the common reference change that Theorem 4.2(3) states is exact, because tr(a⁻¹ C a⁻ᵀ) ≠ tr C for non-orthogonal a.
   - **Where:** `vfe3/model/minimal_agent.py:921, 931`; `vfe3/model/relational_operators.py:936-940, 1188, 1283`.
   - **Measured:** the loss changes by 7.0e-4 at f = 1e-4 and by 7.0e-2 at f = 1e-2, with cond(a) = 12.
   - **Comment:** the comment at `relational_operators.py:1279-1283` calls tr(C)/K "the invariant".
   - **Evidence:** run.
5. **Medium.** The baseline launcher never checks its data against the base run (`train_baseline.py:84-137`). `DATASET`, `DATA_SEED` and `MAX_TOKENS` are free constants, compared with neither the base run's `config.json` nor its `provenance.json`, and `validate_token_range` only checks `id < V`. ### Performance

20. **Medium (active).** `amp_dtype = "bf16"` does nothing on the active route. A dispatch count under CPU autocast found 0 of 3,198 forward and 0 of 4,401 backward operations producing a reduced dtype. Every contraction runs in an autocast-disabled island, which `inactive_fields` already states. The setting costs dispatch overhead and buys nothing; set `amp_dtype = None` on this route (run; CUDA behavior inferred from the same islands).
21. **Medium (active).** The mean-field label step repeats work (`vfe3/model/minimal_agent.py:373, 404-418, 444-453`):
    - Each layer runs 11 Cholesky factorizations, 4 of them duplicates: B_j is factored three times and V_Q three times.
    - B_j⁻¹ is formed twice under autograd.
    - `projected_gaussian_kl` is called without `symmetric_inputs = True`, so it runs two extra symmetry checks per layer.

    The label step is 34% of forward operations, about 40% of them validation. Skipping only the symmetry check saved 3.7% of forward plus backward, with bitwise-equal outputs. Reusing the factors and dropping the autograd on the query log-determinant, a constant per softmax row, is estimated at about 15% of forward operations (run).
22. **Low (active).** A training forward makes six host synchronizations: four `status.tolist()` calls (`vfe3/model/relational_operators.py:870`, one per layer), one `torch.unique` and one deferred-scope read. An optimistic check that reruns the whole forward in float64 only if any layer flags would cut the four to one and make the step capturable by CUDA graphs (run).

### Theoretical and mathematical improvements

Each proposal below follows from the manuscript or from a verified defect. Proposals T1 to T3 come from the theory investigator and T4 to T6 from the geometry investigator. The numerical support for T1 to T3 comes from numpy reimplementations; T5 was run on repository code. Each would be a new option or a new diagnostic rather than a silent change to an existing run.

**T1. A per-layer ELBO for the minimal and prototype agents.** High value, low effort; diagnostic only.
- **Mean field, per receiver:** L_i = Σ_h [−Σ_j β_ij KL(N(a⁺, A⁺) ‖ N(b_j, B_j)) − KL(β_i ‖ π_i) − (d/2)(1 + log 2π) − ½ log det A⁺] − KL(N(ξ⁺, P) ‖ N(ξ, C)), with a⁺ = S_h ξ⁺ and A⁺ = S_h P S_hᵀ.
- **Exact single-head evidence:** log p(o) = logsumexp_j(log π_j − c_ij) − (d/2) log 2π.
- **Prototype evidence:** log Σ_a π_a N(ν_a; ξ, C + Λ_a), at O(MK) per token, the same as the label logits.
- **What it buys:**
  - It checks that every layer is a monotone CAVI step on a stated objective.
  - It measures the mean-field gap in nats: 0.17 to 1.19 per receiver after one sweep, 0.13 to 0.57 after eight. That says whether more sweeps or exact inference are worth their cost.
  - It replaces the canonical free-energy diagnostic, which scores flat alignment rather than these readouts' objective.
- **Where:** beside `_label_staleness` in `vfe3/model/minimal_agent.py` and in `prototype_mean_field_posterior`.
- **Caution:** the evidence is unbounded above as S, T → 0 and n → 0, because the record is declared rather than observed. It must not enter the training loss.

**T2. A spread-corrected mean-field covariance.** Medium-high value, low effort; this addresses item 9's context-independence.
- **Formula:** C⁺ = P + Σ_h P S_hᵀ R′_h S_h P, with R′_h = Σ_j β_j d_j d_jᵀ and d_j = B_j⁻¹(b_j − a⁺) − Σ_k β_k B_k⁻¹(b_k − a⁺). This is a linearized law of total variance over the labels, and it is positive definite by construction.
- **Cost:** O(B·H·N²·d²), the same as the kernel's `_centered_spread`, which can be reused.
- **Measured:** on 200 random single-head instances the median KL to the exact posterior fell from 0.188 to 0.072, and 99.5% of instances improved.
- **Contract:** the result is a hybrid of CAVI and assumed-density filtering, so it belongs under a new `predictive_covariance` value.

**T3. A second-order expected log-loss for the linear decoder.** Medium value, medium effort.
- **Formula:** E_q[−log p_y] ≈ CE(μ) + ½[Σ_v p_v ((W∘W)σ)_v − Σ_k σ_k (Wᵀp)_k²].
- **Measured:** at V = 2,000, K = 20 and variance 0.01, 0.05 and 0.2, the delta method gives 2.952, 3.075 and 3.535 against Monte Carlo values of 2.953, 3.074 and 3.518. The current plug-in gives 2.922 at all three.
- **What it buys:** it gives the final covariance, which the linear decoder now ignores, a role in the loss, at one extra V×K GEMM in `decode_ce_linear_chunked`.
- **Risk:** it pushes Σ toward its floor. Run it as an ablation arm first.

**T4. A spread projection on each frame block.** High value, low effort; this fixes item 3.
- **Bound:** κ₂(e^X e^Y) ≤ exp(spread(sym X) + spread(sym Y)), where spread is λ_max − λ_min. It was checked over 20,000 random draws and is tight (largest ratio 1.000).
- **Operation:** after each accepted step, for each active row and head block, take S₀ = sym(B) − tr(B)/d·I, eigendecompose it, and clamp the eigenvalues to [−c, c]. Rotation and determinant stay free.
- **Guarantee:** a chosen κ_max, for example 1e4, keeps the fp32 pair residual near 1e-5, far below the abort.
- **Where:** a new mode in `project_phi_parameter_rows_`, called from `train.py:1176-1218`.
- **Cost:** one no-grad eigendecomposition of 10×10 blocks per active row. Parameter names are unchanged. A zero-cost soft variant applies a separate decoupled decay to S₀ only.

**T5. A prior-anchored covariance floor.** Medium value, low effort; this fixes item 4.
- **Formula:** Σ⁺ = U C⁺ Uᵀ + f·Σ_p,x_i, the token's prior covariance in local coordinates; for the diagonal family, + f·σ_p.
- **What it buys:** it is frame-free in local coordinates, so it is exactly reference-invariant and site-covariant. It does not compound with depth, since every layer keeps C ⪰ f·C⁽⁰⁾, and it is cheaper than forming diag(U Uᵀ).
- **Measured:** a relative floor f·C restored invariance to 4.4e-15 in the geometry investigator's run, but that floor compounds with depth, which is why the code avoids it. The prior-anchored form keeps the invariance without compounding.

**T6. Smaller items.**
- **Noisy-key kernel routing at τ = 1 for the kernel arms:** score D(q_Q ‖ N(b, V_K + n_h I)) with a learned per-head noise in place of κ√d, which makes the routing objective again the KL of a declared joint (manuscript line 1089).
- **A channel-noise M-step as a diagnostic:** the collapsed stationarity condition is solved by scalar Newton after one small eigendecomposition per source. The uncollapsed closed form is wrong by a factor of 2.6, so it should not be used.
- **Exact prototype inference on the diagonal layout:** about 1.3e7 pair elements per layer, and `block_mlp_inference = "exact"` already exists.
- **A polar chart U = e^A e^S for block_glk:** it reaches all of GL⁺(d) and inverts without an LU, but most of its payoff is already in T4.

**Rejected:** a holonomy regularizer on the frames. With one shared generator, H_ijk = U_k e^L U_k⁻¹, so its conjugacy class does not depend on the frames and its gradient with respect to them is zero.

## Test results

The CPU suite was run once at `6b872b4` in the scratch environment: Linux, torch 2.14.1 (CPU), CUDA hidden, two pytest-xdist workers. It ran 4,610 tests in 765 s: 40 failed, 25 were skipped and none errored. The user's lane on October 11 recorded 4,583 passed on Windows. Every failure here was attributed to the environment:
- **Missing dependencies or hardware (about 15):**
  - scikit-learn is not installed, which fails the 10 semantics-vector tests and probably the 4 contextual and multi-seed semantics tests;
  - one figure test needs a CJK font;
  - one test needs an NVIDIA driver.
- **Matplotlib figure leaks (2):** these tests fail only after other tests in the same worker leave figures open; they pass when run alone.
- **Platform-sensitive comparisons (about 20):**
  - 12 equal-head goldens;
  - 4 shared-content-chart tests;
  - 1 latent-link test that differs in the last bit;
  - 3 numeric-toggle tests that compare values near 5e7 with an absolute tolerance of 5e-5 (relative difference 7.5e-5);
  - 1 fp32 positive-definiteness test at condition 1e6;
  - 1 Gram-solve comparison at rtol 1e-12.

  All of these reproduce when run alone on this platform and are not code defects on the user's lane. They do mean these tests certify one platform and torch build, not the arithmetic.

The GPU lane was not run.
