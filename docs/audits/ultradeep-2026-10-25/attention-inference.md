## Correctness finding in a diagnostic oracle

### AI1. The fixed-context receiver cost reduces per-coordinate entropy weights on the wrong axes

**Location:** `vfe3/gradients/full_link.py:600-607`; compare the supported coordinatewise branches at `full_link.py:553-554`, `full_link.py:653-660`, and `full_link.py:934-943`.

**Severity:** low (P3).

**Evidence:** `FullLinkContext.c` admits a per-coordinate tensor with the same shape as the mean. The analytic force uses `_diagonal_weight(c, mu) / sigma`, and the closed-form covariance uses `Lambda.diagonal() / _diagonal_weight(c, mu)`. The scalar `full_link_cost`, when `profile is None`, instead executes `logdet = covariance.log().sum(-1)` followed by `(.5 * quadratic - linear + .5 * trace - .5 * c * logdet).sum()`. This contracts the coordinate axis before applying its weights. For mean/variance shape `(1,3,2)` and `c.shape == (1,3,2)`, the resulting `(1,3)` log determinant cannot broadcast against `c`, so the routine raises. At `(1,1,2)`, broadcasting succeeds but replicates the already-summed trace and multiplies the summed log determinant by each coordinate weight; both the scalar and its derivative disagree with `full_link_gradients`. The correct diagonal entropy contribution is `-.5 * (c * sigma.log()).sum()` when `c` is per coordinate. `full_link_cost_parts` already implements that contraction at lines 936-937.

**Fix:** Apply coordinatewise weights before reducing the diagonal log variances, sharing the contraction used by `full_link_cost_parts`.

**Falsifies:** A fixed context with unequal coordinate weights must return the same energy difference and covariance derivative as an explicit coordinatewise quadratic energy at both `(B,N,K)=(1,3,2)` and `(1,1,2)`.

**Trigger and consequence:** This affects callers that form a fixed `FullLinkContext` with vector `c`, including the pattern `dataclasses.replace(context, profile=None)` already used by receiver oracle tests. It can prevent or invalidate a regression check of per-coordinate frozen-alpha receiver updates. It is not a demonstrated training failure: the live context built by `build_full_link_context` retains its profile; `full_link_cost` takes lines 586-593, recursively evaluates a coupling-only cost with scalar zero `c`, then adds the profiled self-term separately. The production gradients and closed forms retain their coordinatewise handling.

**Reproduction:** The coordinator executed the float64 CPU fixture in `probe_full_link_oracle.py`; its receipt is `probe_full_link_oracle.json`. It uses `mu=zeros(1,3,2)`, `sigma=[2,3]` repeated across the three rows, `Lambda=I_2` repeated across rows, `eta=mu`, and `c=[1,2]` repeated across rows. At `N=3`, `full_link_cost` raises `RuntimeError: The size of tensor a (2) must match the size of tensor b (3) at non-singleton dimension 2`; the independent reference `.5 * (sigma - c * sigma.log()).sum()` and `full_link_cost_parts` both give `3.164442363155753`. At `N=1`, the reference and parts give `1.0548141210519175`, whereas `full_link_cost` gives `2.3123607961579173`. The absolute error is approximately `1.25755` on a scalar of magnitude `1.05481`, far above float64 roundoff. An initial audit-probe serialization assumption was corrected because the parts function returns a tuple; no implementation code changed. The covariance-derivative comparison is a proposed regression check, not an executed result in this receipt.

**Prior coverage:** `tests/test_full_link_gradients.py:112-135` compares the fixed-context oracle with the literal Gaussian energy but uses scalar per-token alpha. `tests/test_projected_gradient_receiver.py` also uses frozen contexts; the inspected tests do not cover a fixed context with unequal coordinate weights and `N != K`.

## Additional evidence for the cache finding already reported in the gauge lane

The coordinator reproduced an API-level temperature cache failure in `probes_contracts_artifacts.json`, key `temperature_cache`. `free_energy._sqrt_dims` at lines 93-104 saves a tensor created in the current execution mode. If unequal dimensions `[1,3]` first populate this cache under `torch.inference_mode()`, a later direct call `attention_tau(torch.ones(2, requires_grad=True), [1,3])` raises `RuntimeError: Inference tensors cannot be saved for backward` at line 90. This extends the same cache-lifetime failure class as the CG finding; it should not be counted as another live training defect.

The initially suspected standard learned-temperature route is not established affected. `model/stack.py:115-116` passes configured constant `kappa_beta` through `attention_tau`, which makes a fresh product. `RelationalOperators.routing_temperature` applies its learned multiplier afterward at lines 2172-2174. The direct differentiable-`kappa` API is the demonstrated scope. A cache fix should construct reusable constants outside inference mode or clone them into ordinary tensors before later autograd use; its regression check should cover the execution-mode transition, not just device/dtype changes.

## Focused improvement

Extend the existing scalar-versus-analytic receiver oracle check to `state_dependent_per_coord`, remove the profile explicitly to test its frozen majorizer, use unequal coordinate weights, and select `N != K` so accidental broadcasting cannot hide the error. A one-token variant is also useful because it exercises the silent wrong-value case. This is a focused check of an independent scalar functional against its force, rather than a duplication of implementation syntax.
