## Tests independent of the launcher and of the VFE3Config defaults

The user required that no test fail because a configuration toggle was set: a test of a particular path sets the toggles that select it, and neither the launcher dictionaries nor the `VFE3Config` defaults may change what a test exercises or whether it passes. On `018c0d0` the CPU lane had 13 failures caused by the launcher's values and the latest default changes.

`config_from_serialized` now fills a field that a serialized record lacks from `vfe3/config_history.py`. Since `serialize_config` writes every field, a record lacks a field only when it predates it, and it then ran the field's introduction value. The table holds the caa0114 default snapshot committed at 395a430 (taken before the later default changes and checked against the caa0114 source) and the eighteen fields added since, at the values of the commits that introduced them. The `_HISTORICAL_DEFAULT_PINS` rows and era rules still take precedence, and a field newer than the table takes the current default. A changed default therefore needs no pin row and fails no test. Loading the run records under `vfe3_runs/` (twelve at the first check, nine at the last, as runs were renamed and removed meanwhile) gave identical configs with and without the new fill. The former guard `test_no_field_default_changes_without_a_pin_row` is replaced by tests of the frozen table, of the reload of a record lacking each field (including under simulated default changes), and of the serialize round trip.

Tests that exercised a path through `live_config` now build the frozen reference route (`reference_config`, or the new `reference_k8_config` at the live profile's K = 8 in two heads) and set the toggles their path needs. The tests whose subject is the launcher route still read `train_vfe3.config`, but they set what they depend on: a family-matched KL decoder, the frame transport for the frame-exponential check, the frame-diagonal envelope, and a lifted router ceiling where the tiny cap clamps a layer dead. Their Richardson check re-measures a mismatch at h/4, where an O(h^4) truncation shrinks and a backward defect does not. Assertions on a field's default or on a driver's chosen values became assertions on the test baseline and on validity, and tests that replace a driver baseline or run the launcher set the `fully_gauge_covariant` switches themselves. The data-identity deferral test's host-check wrapper forwards the `detail` keyword.

## Cost of the frame condition bound

A K = 128 launcher run (four heads of d = 32, V = 50,257) with `phi_frame_condition_max = 20` slowed from 252 ms per step at step 500 to 616 ms per step averaged over steps 500 to 1000. The run `38.50_wikitext-103_K128_before-opt`, whose live settings differ only in that the bound is off, held 255 ms per step through step 15,000. The cost was in `bound_phi_frame_condition_`, which runs after every accepted update, and it had three sources. The float32 screen √2‖S₀‖_F ≤ 2c is loose by up to √(d/2) = 4 at d = 32, so as the frames grew, a growing set of rows inside the bound was eigendecomposed on every call. Those rows were processed in chunks of 341 with host reads in every chunk and a 64-step bisection of about 590 operations. The float32 eigendecomposition certificate (tolerance 64dε, about 2.4e-4) computed its products under the process policy `fp32_matmul_precision = "high"`, and TF32 rounding of 2^-11 fails it almost always, which sent nearly every flagged row through the float64 recomputation as well.

The bound now runs under `ieee_fp32_matmul`. Rows the screen flags go to a second certificate, `_window_certified`: two Cholesky factorizations prove that every eigenvalue of S₀ lies in [t − c, t + c], with a shift that covers the Cholesky backward error (Higham 2002, Theorem 10.3; Rump 2006). The center t is the spectrum midpoint cached per model and table from the row's last eigendecomposition. The certificate holds for any t, so the cache decides only how often it passes and never a result. A row inside the bound therefore reaches the eigensolver once, and again only after it leaves its window. The spread projection takes its piecewise-linear root exactly from the 2d breakpoints, in a fixed 37 operations. Chunks are sized at the working dtype under a 256 MiB budget (1,024 decomposed rows at the live shape), and the float64 recomputation of uncertified float32 rows runs once after all chunks. A table now costs at most three host reads, plus the convergence check inside each `torch.linalg.eigh` call. The projection target and the storage margin are unchanged, so projected rows agree with the previous implementation to float32 rounding.

Verification: `tests/test_frame_bound_cost_20261021.py` failed on the previous implementation (36 repeated decompositions where none should occur, the "high" policy inside the eigensolver, 17 host reads, 587 operations in the spread projection). It now passes, together with the existing frame-bound tests and a pass over the 30 test files that import `gauge_optim` or set the bound (618 passed, 0 failed, CPU, three workers). The CUDA test at the live head shape is registered in `CUDA_TESTS` but has not run, and the step time of a live run with the bound on has not been re-measured. The run that was in progress keeps the code it loaded at launch.
