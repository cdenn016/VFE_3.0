# Changes for October 21, 2026

## Remediation of the 2026-10-20 audit (groups A, B, C, E and G of the punch list)

The user asked for the punch-list groups A (live-route defects), B (stability toggles, without the learning-rate scaling items), C (instrumentation), E (tests) and G (documentation) of `docs/audit-results_2026-10-20.md` and `docs/investigations/2026-10-20-gradient-spikes-k128plus.md`; groups D (performance) and F (experiment drivers) were deferred. Five lanes worked in isolated worktrees from `88f5afa` on CPU only, since the GPU was unavailable, and were merged into the local branch `claude/audit-fixes-20261020`. The two learning-rate scaling items (a frame rate proportional to 32/d and a muP-style rate switch) were not implemented at the user's direction.

The router lane made `routing_kl_max_reference="query_shifted"` subtract, besides the query-only row constant, the mean key log-volume over the row's admissible keys, so the clamped cost is invariant under a joint rescaling of a head's comparison maps and a head can no longer be pushed onto the cap by map growth along that flat direction (audit item 1). The earlier clamp is retained as `"query_shifted_v1"`, and configurations saved with `"query_shifted"` before the change, recognized by the absence of the new field `relational_score_weight_decay`, reload as v1. That field (default 0) adds an opt-in decay on the comparison maps (item 9). Per-head score-term medians are written to `diagnostics/score_terms.csv` (item 38), the logged routing free energy is that of the absolute cost (item 39), the tiny live profile scales `kl_max` by head width so its router gradients are nonzero and asserted (item 5), and a frozen tiny profile of the 30.37 reference route pins that route independently of the launcher (item 23).

The training-loop lane writes the crash record and the stop line before the emergency checkpoint (item 12); adds positions, steps since last occurrence, per-head frame condition and a post-update forward probe of the maximum belief variance and per-position CE to spike records, and drops the "hard batch" cause label (item 11); freezes the spike monitor's EMA on spike steps; adds interval medians and upper quantiles of `block_variance.csv`; extends the headline router and belief columns and the collapse alarms to every layer (item 14); logs allocator and clock telemetry (item 20); records a measured matmul FLOP count and corrects the decode FLOPs (item 48); reports test at the validation-selected weights beside the final weights (item 7, run-folder naming unchanged); and removes the empty `diagnostics` field (item 73).

The optimizer lane added two opt-in toggles whose defaults leave the optimizer unchanged: `m_phi_sparse_rows`, a row-lazy AdamW for `phi_embed` with per-row bias correction and checkpointed per-row step counts, and `m_decode_update_mode="fisher"`, a natural-gradient step for the untied decode bank in the Gaussian Fisher metric diag(1/t, 1/2), count-weighted with the count floored at one so non-target rows still step, reusing `m_table_fisher_lr` and `m_table_fisher_trust_radius`.

The remaining lanes fixed the post-hoc and semantics readers for `gaussian_frame_diagonal` (item 26), refused that family with a tied bank and a prior-bank decoder (item 59), made `vfe3.contracts` importable on Python 3.10 (item 74), guarded batched CPU LU-family calls that are wrong under multithreaded MKL at K of 160 and above (item 28), recorded which diagonal-moments kernel ran (item 45), routed the unselected CUDA tests and removed the empty slow lane (item 22), restored process-global state between tests (item 24), added a CUDA parity and timing test of the fused diagonal-moments kernel that has not yet run on a GPU (item 15), and moved the decode finite-difference probe to float64 (item 60). The documentation lane corrected the README and stale docstrings (items 67 to 70), derived the run-record contract strings from the configuration (item 25), documented the reconstructed WikiText-103 GPT-2 cache recipe (item 30), added 35 missing fields to the `train_vfe3.py` dictionary at their defaults (item 66) and removed orphaned code (item 72). The correction to `docs/audit-results_2026-10-17-36.41-comparison.md` on count-1 rows and the Fisher trust radius was applied in the main checkout, where that file is untracked.

Every change was tested for exactness against a copy of the prior code as an oracle; nothing was approximated, and no GPU timing exists, so step-time gains on the RTX 5090 are unmeasured.

The covariance-update lane counts the batch axis in the routed-spread tile size and checkpoint decision (items 6 and 16), truncates both spread loops to the causal source range when the routing prior tensor is strictly causal, detected from the tensor rather than the prior's name (item 18), and removes two of the four large layout copies of the blockwise chain plus several smaller ones (item 17, partial: the remaining two need a relayout to stay on plain GEMMs). ## Tests independent of the launcher and of the VFE3Config defaults

The user required that no test fail because a configuration toggle was set: a test of a particular path sets the toggles that select it, and neither the launcher dictionaries nor the `VFE3Config` defaults may change what a test exercises or whether it passes. On `018c0d0` the CPU lane had 13 failures caused by the launcher's values and the latest default changes.

`config_from_serialized` now fills a field that a serialized record lacks from `vfe3/config_history.py`. Since `serialize_config` writes every field, a record lacks a field only when it predates it, and it then ran the field's introduction value. The table holds the caa0114 default snapshot committed at 395a430 (taken before the later default changes and checked against the caa0114 source) and the eighteen fields added since, at the values of the commits that introduced them. The `_HISTORICAL_DEFAULT_PINS` rows and era rules still take precedence, and a field newer than the table takes the current default. A changed default therefore needs no pin row and fails no test. Loading the run records under `vfe3_runs/` (twelve at the first check, nine at the last, as runs were renamed and removed meanwhile) gave identical configs with and without the new fill. The former guard `test_no_field_default_changes_without_a_pin_row` is replaced by tests of the frozen table, of the reload of a record lacking each field (including under simulated default changes), and of the serialize round trip.

Tests that exercised a path through `live_config` now build the frozen reference route (`reference_config`, or the new `reference_k8_config` at the live profile's K = 8 in two heads) and set the toggles their path needs. The tests whose subject is the launcher route still read `train_vfe3.config`, but they set what they depend on: a family-matched KL decoder, the frame transport for the frame-exponential check, the frame-diagonal envelope, and a lifted router ceiling where the tiny cap clamps a layer dead. Their Richardson check re-measures a mismatch at h/4, where an O(h^4) truncation shrinks and a backward defect does not. Assertions on a field's default or on a driver's chosen values became assertions on the test baseline and on validity, and tests that replace a driver baseline or run the launcher set the `fully_gauge_covariant` switches themselves. The data-identity deferral test's host-check wrapper forwards the `detail` keyword.

Verification: the CPU fast lane (12 workers) ran with a scratch plugin that rewrote `train_vfe3.config`, the other driver dictionaries, the driver switches and up to 47 `VFE3Config` defaults in memory, under six settings: the launcher of 88f5afa, the current launcher, two route-flipped launchers (minimal agent with comparison RoPE, and kernel without RoPE, both on `gaussian_full` with seven flipped defaults), 47 flipped defaults, and route-flipped driver dictionaries with both covariance switches on. Each gave 6,056 passed, 0 failed, 9 skipped and 2 expected failures. `run_cpu_tests.py` then gave 6,067 tests with 0 failures in the fast lane (11 skipped, counting the two expected failures) and 31 with 0 failures and 7 skipped in the Triton interpreter lane. No CUDA test ran; the CUDA live-route test was edited without being executed.
