# Changes for October 25, 2026

## Block MLP tied across depth

Added `block_mlp_tie_layers` (default `False`). When `True`, one block MLP is built and applied at every layer, for every `block_mlp_mode`. Depth then applies one set of dynamics, and the template or component labels of `prototype_agents` and `cue_result_memory` keep their meaning from layer to layer. The module list holds the same object `n_layers` times, so the state dict keeps the per-layer keys `block_mlps.<layer>.*` as aliases of one tensor and `parameters()` yields each shared parameter once. The untied path builds exactly as before.

Consumers that would have treated the shared bank once per layer were changed. The optimizer lists each undecayed template parameter once, the working-variance calibration calibrates a shared module once on its first layer's input, and the build metadata, the artifact fallback and `scaling.py` count the parameters once while the FLOPs stay per layer. Loading a checkpoint whose per-layer block-MLP entries differ (one saved from an untied model) into a tied model raises instead of keeping the last layer's values; a tied checkpoint loads into an untied model and gives every layer the same bank. The field is in `VFE3Config`, the launcher at its default, the test profile and the introduction-value table, and is reported inactive without a block MLP or with one layer. No live setting changed.

Tests: `tests/test_tied_block_mlp_20261025.py` (12 tests) loads a tied model's state into an untied model for the coordinate, prototype and cue/result routes and checks equal losses and that the tied gradient of every shared parameter equals the sum of the untied per-layer gradients; it also checks topology and parameter counts, optimizer groups without duplicates, the load guard and round trip, one calibration, and the configuration field. A broader CPU pass over 26 files (block-MLP registry, configuration validation and history, launcher, prototype and gauge block MLPs, block coordinates, scaling, posthoc consumers, optimizer toggles, per-type hidden bias, checkpoint averaging, weight EMA and the cue/result memory) ran 547 tests, all passing. CPU only, one thread, tiny models. No training or GPU run was performed.

The tied-bank entry above was written with PR #138 but not committed with it: `docs/` is ignored and daily logs are force-added, and `git add -A` skipped this file. It is committed with the diagonal-carrier branch below.

## Diagonal cue/result carrier on gaussian_frame_diagonal

`cue_result_memory` now also runs on `family="gaussian_frame_diagonal"` (plan Task 6, the scalable reference carrier). That family stores the reference variances $c_i = \operatorname{diag}C_i$, so the record covariance is diagonal and the exact posterior is elementwise: $W_a = \operatorname{diag}(\lambda_a + c)$, $m_{X,a} - \nu_a = \lambda_a/(\lambda_a + c)\odot(\xi - \nu_a)$, $P_{X,a} = \operatorname{diag}(\lambda_ac/(\lambda_a + c))$, and with $F_a = I + U_aV_a^\top$ the result variances are $q + p + 2p\odot\sum_rU_{\cdot r}V_{\cdot r} + \operatorname{diag}(U_a(V_a^\top P_{X,a}V_a)U_a^\top)$, $O(Kr^2)$ per (token, component), or $\sum_lF_{kl}^2p_l$ for a dense $F_a$. `cue_result_diagonal_posterior` in `vfe3/model/cue_result_memory.py` returns the result mean and the exact diagonal of the result mixture's covariance, the M-projection of the exact result law onto diagonal Gaussians in the reference chart; within-component and between-component off-diagonal covariance is discarded by that projection. Rows and components are tiled by the tile budget, with each tile checkpointed under gradients and merged by the coordinatewise law of total variance. The block dispatches on the covariance it receives (dense or (..., K)), the reference block passes the stored variances in and stores the result variances back without forming a dense $C$, and the configuration admits the mode on the frame-diagonal family (still reference coordinates, exact, posterior, no dropout, no EM) while every other frame-diagonal restriction is unchanged.

Measured cost (one CPU thread, K = 128, M = 1024, 64 tokens, forward and backward): 0.61 s with rank-2 regression and 6.5 s with dense $F_a$, against 0.001 s for the GELU MLP at the same width. The earlier estimate of about five times the MLP was wrong: the per-pair arithmetic is small, but the token-dependent $1/(\lambda_{ak} + c_{ik})$ prevents a GEMM, and the PyTorch implementation makes about thirty elementwise passes over a (tokens, M, K) tensor, so it is bound by memory traffic. A fused kernel that keeps the per-pair work in registers would be needed before GPU-scale training; no GPU timing was taken.

Tests: `tests/test_cue_result_diagonal_20261025.py` (14 tests) checks the diagonal kernel against the dense exact kernel at $C = \operatorname{diag}c$ for dense, rank-1 and rank-3 regression including a reversed response (means, log weights and evidence equal, variances equal the dense diagonal, with nonzero discarded off-diagonal covariance), tiling with checkpointed gradients, float64 `gradcheck` through tiles, layout dispatch, the frame-diagonal reference block and its passive invariance, the configured model path untied, tied, with a LayerNorm pushforward and with dense regression, and the configuration boundary. A broader CPU pass over 22 files, including the frame-diagonal family suites, ran 515 tests, all passing. CPU only, one thread; no training or GPU run.

## Regime belief carried through depth

Added `block_memory_regime_transition` (`"off"` default, `"sticky"`, `"learned"`) with `block_memory_regime_beta` (1.0) and `block_memory_regime_stay` (0.9), for `cue_result_memory` with tied banks (`block_mlp_tie_layers=True`, enforced). The component (regime) posterior is carried through depth as a hidden-Markov state: layer $\ell+1$'s per-token prior is $\hat\pi_b(w^\ell T)_b^\beta$, the posterior of the reference prior after a Dirichlet record of the predicted regime law $w^\ell T$, whose normalizer is independent of $b$. `"sticky"` is $T = sI + (1 - s)\mathbf 1\hat\pi^\top$ with one learned stay probability and no $M\times M$ tensor; `"learned"` is a row-softmax $M\times M$ table initialized at $sI + (1 - s)/M$. Both train without weight decay. $\beta = 0$ recovers the shared prior exactly. The carried record is the network's own earlier belief and is not independent of the current cue record; $\beta < 1$ tempers that reuse but is not derived to correct it, which only an experiment can settle.

Both cue/result kernels accept a per-token prior (..., M). The stack threads a per-forward `regime_state` dict through the blocks (as it already does for the latent-link `link_state`): each layer's block reads `"previous"` and writes `"current"`, promoted after the block, so no state lives on the module. Parameter counts include the transition parameters (1 or $M^2$). The three fields are in `VFE3Config`, the launcher at their defaults, the test profile and the introduction-value table; they are inactive off `cue_result_memory`, and beta and stay are inactive with the transition off. No live setting changed.

Tests: `tests/test_regime_belief_20261025.py` (14 tests) checks the per-token prior of both kernels against row-by-row shared priors with tiling, the block driven through three layers against an explicit HMM recursion (explicit $T$, `MultivariateNormal` record densities) for sticky and learned transitions at $\beta = 1$ and $0.4$, the $\beta = 0$ reduction at block and model level, the transition initialization and counts, the configured dense and frame-diagonal model paths with nonzero transition gradients and undecayed transition parameters, and the configuration. A broader CPU pass over 24 files, adding the latent-link, edge-link and intervention suites because the stack and block signatures changed, ran 701 tests, all passing. CPU only, one thread, tiny models; no training or GPU run.

## One switch for the principled exact route; minimal agent on gaussian_frame_diagonal

Added the launcher toggle `principled_exact_route` (default `False`) beside `fully_gauge_covariant`, with `vfe3/exact_route.py`. At launch it overrides the keys the route fixes: exact minimal-agent attention with its posterior covariance; the exact cue/result memory in reference coordinates with no block norm, tied across depth with the regime belief carried (`sticky` unless `learned` is chosen); the covariant diagonal family `gaussian_frame_diagonal` with the `diagonal_chunked` decoder at `decode_tau=1` and an untied bank; `rope_mode="comparison"` when `comparison_invariant` (a kernel-router mode) was set; and everything `fully_gauge_covariant` overrides on top. `principled_exact_route_failures` re-derives every requirement and the launcher refuses a run with any unmet one; the overrides are logged and written to config.md. It leaves the memory's regression rank and result noise, the regime beta and stay, routing prior, floors, learning rates, shape and numerics as configured. Resolved against the current launcher it makes 15 overrides with no unmet requirement (16 against the working-tree launcher, which also switches `predictive_covariance` to `moment_matched`).

To make the route reachable on a diagonal family, the minimal-agent readout now runs on `gaussian_frame_diagonal`: it conditions on $(\xi_i, \operatorname{diag}c_i)$ through the identity frame, stores $c_i^+ = \operatorname{diag}C_i^+$ (the family's reference M-projection) with the floor in reference coordinates, and returns the mean through $U_i$. The configuration and the operator constructor no longer reject that combination. The local-diagonal family `gaussian_diagonal` is not used by the route: its diagonal truncation in local coordinates does not commute with frame changes, and the memory would need the dense reference covariance.

Tests: `tests/test_exact_route_20261025.py` (5 tests) checks the frame-diagonal minimal agent against the same operator on the full covariance $U\operatorname{diag}(c)U^\top$ (equal means, $c^+$ equal to the diagonal of the reference posterior covariance, nonzero discarded off-diagonal covariance, passive invariance), the toggle on the test baseline (every requirement met, idempotent, a learned transition kept), the reporting of unmet requirements, a training step of the resolved tiny model, and the launcher (default off, resolves with no unmet requirement). A broader CPU pass over 25 files, adding the minimal-agent, frame-diagonal and gauge-covariant suites because the readout and the family validation changed, ran 603 tests, all passing. CPU only, one thread; no training or GPU run.

The launcher's `block_memory_regression_rank` is set to 2 at the author's request (the `VFE3Config` default stays `None`, the introduction value, so saved runs and other launchers are unchanged). Rank 2 is the smallest rank at which $F_a = I + U_aV_a^	op$ can rotate or reverse a plane, the response same-state conditioning cannot produce; on the diagonal carrier it measured about 0.6 s per 64 tokens against 6.5 s for a dense $F_a$ (one CPU thread, K = 128, M = 1024), with $2MKr pprox 0.5$ M parameters for a tied bank at K = 128 against 16.8 M dense.

## Principled exact route in ablation.py

`ablation.py` gains the `principled_exact_route` switch beside `fully_gauge_covariant`. When it is set, `_resolved_sweep_baseline` applies `principled_exact_route_overrides` to `BASELINE_CONFIG` before the arms, and `_require_exact_route` refuses any cell (at startup in `validate_sweeps` and again in `run_single`) whose resolved config fails `principled_exact_route_failures`, unless its sweep declares `leaves_exact_route`. `BASELINE_CONFIG` gains the memory keys at the launcher's values (`block_mlp_tie_layers=False`, `block_memory_regression_rank=2`, result noise 0.01, regime off, beta 1, stay 0.9), so the route's memory does not fall back to the dense default.

Nine `exact_route_*` sweeps carry the route resolved from `BASELINE_CONFIG` in their `requires`, so they run on the route with the switch on or off. `exact_route_components` (the one sweep allowed to leave the route) compares the route with arms that each replace one component: `decode_tau=0.1`, the regime not carried, an untied memory, mean-field attention, the kernel readout, the coordinate MLP, and no block MLP. The others vary what the switch does not fix: regression rank (1, 2, 4, 8), regime beta (0, 0.5, 1, 2; 0 is the shared prior at every layer), regime stay (0.5 to 0.97), sticky versus learned transition, result noise ratio (0.001 to 0.1), memory size (expansion 2, 4, 8), minimal-agent channel noise (0.3 to 3), and predictive covariance floor (1e-5 to 1e-3).

`_sweep_base_settings` now starts from the resolved baseline rather than the literal `BASELINE_CONFIG`, so under either switch a sweep's added base cell sits at the value the cells actually run (before, under `fully_gauge_covariant`, a base cell could be labeled at an overridden literal). `vfe3/run_artifacts._DECLARATIVE_DRIVER_NAME` lists `principled_exact_route` as a declarative launcher toggle, as it does `fully_gauge_covariant`. Tests: `tests/test_ablation_exact_route_20261025.py` (4); every test matching ablation or sweep passes. Nothing was trained.

## Three-arm frame-capacity comparison

Added and selected `SWEEPS["frame_capacity"]` in `ablation.py`: learned token frames, identity frames without a replacement table, and identity frames with the zero-initialized per-type MLP hidden-bias table. Shared prerequisites pin projected predictive attention with the kernel readout, the per-token encoder, an attention residual in every layer, a coordinate MLP with passthrough covariance, comparison-invariant RoPE, ALiBi, and no positional frame table. The bias table inherits the declared frame learning rate before gauge-off coercion, rather than the independent live bias rate; both tables use AdamW, `phi_weight_decay`, and the phi clipping role. The sweep retains the rest of the working baseline and the other sweep declarations and order.

The three paired model/data-order seeds are `(6, 6)`, `(23, 23)`, and `(54, 54)`, implemented with `DATA_SEED=None`. Schedule seed 20261025 randomizes the three arms within each seed block. No generic baseline is appended, giving exactly nine runs, and `learned_frames` is the reference for the runner's paired differences. All runs inherit the same current budget: 15,000 steps, batch 64, context 128, warmup 250, no early stop, and 122,880,000 training tokens per run. This is a step/token comparison, not a wall-time comparison. The existing validation cadence is retained (300,000 steps, so this budget uses the runner's terminal validation). Both route-enforcement switches remain off. Seed pairing does not assert identical shared initial weights across different architectures.

Validation constructed all nine live configurations without constructing production-sized models, checked the schedule, common position/residual settings, budgets, paired reference, inherited table rate (0.002), and hidden-width fit. At the current K=128, four-head, four-layer shape, the replacement table has 205,852,672 parameters and its four width-1024 slices fit the MLP. Tiny CPU models (V=11, K=4, two heads and layers) had 519 trainable parameters for learned frames, 431 for identity frames, and 519 for identity frames plus bias; optimizer table groups matched in rate, decay, and role. The existing hidden-bias, paired-seed analysis, exact-route guard, and loader-generator checks passed: 24 tests, CPU only, one thread. No training or GPU tests were launched.

## Cue/result tile budget; frame condition bound on the exact route

The cue/result memory's tile budget is the config field `block_memory_tile_mib` (int MiB >= 1, default 32, the value the module constant `CUE_RESULT_TILE_BYTES` had), set on every memory module in `VFEModel._new_block_mlp` (tied and untied). At K = 192, M = 1536 and rank 2 the 32 MiB budget leaves 3 tokens per tile, about 2,700 checkpointed tiles per layer for a 32 x 256 batch, which matches the observed launch-bound GPU (about 11% utilization at 2 GB). `train_vfe3.py` and `ablation.py` set it to 1024, about 113 tokens and 73 tiles per layer; the result does not depend on the budget. `tests/test_cue_result_tile_budget_20261025.py` (12) checks that the dense and diagonal kernels, with a shared or per-token prior, return the same moments, log weights, log evidence and gradients at one pair per tile, a few pairs and one tile (float64, to 1e-12 and 1e-11), that the field is validated, reaches every memory module and is inactive off the memory, and that the tied model with a carried sticky regime gives the same loss and gradients tiled and untiled. No GPU throughput has been measured yet.

At the author's request the principled exact route keeps `phi_frame_condition_max` as configured instead of overriding it to None. The bound is an M-step projection of the frame table to cond_2(U_i) <= kappa_max: every forward pass stays exact inference on the projected parameters, and the forward map stays covariant, but the constraint set is not invariant under U_i -> g_i U_i, so the training trajectory is not gauge invariant and the pure-path flag `no_phi_mstep_chart_cap` is false whenever the bound is set. `principled_exact_route_failures` excuses that flag only when the frame bound is its sole cause (the chart-norm ball sets the same flag and is still refused), and config.md records `fully_gauge_covariant` as true for the route only when the bound is None. The launcher test no longer pins the live `principled_exact_route` value.

Pre-existing failures on origin/main, unchanged here: `test_audit_20261017_l5_config::test_inactive_fields_agree_with_two_executed_steps[launcher, relative_floor]` (`decode_covariance='encoded'` is unmarked but bitwise inert on those routes) and `test_audit_20261016_integration::test_pushforward_moment_is_admitted_where_pushforward_is` (`block_mlp_covariance_floor` not marked inactive).
