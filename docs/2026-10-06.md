# October 6, 2026

## train_baseline.py set up against the 34.48 run

The conventional-transformer launcher now derives its arm from the K=128, 4-head, 4-layer run `vfe3_runs/34.48_wikitext-103_K128_block_glk_linear_mlp_s6` (preset `k128_exp`, now `BASE`). `BaselineConfig.matched_to` copies that run's step budget (150,000 steps, 614.4M training tokens, five times the 30,000 steps of the earlier 90.15 baseline), warmup, learning-rate floor, gradient clip, bf16 autocast, fp32 matmul precision `highest` (the 90.15 baseline used `high`), context 128, evaluation stride 32, batch 32, evaluation and checkpoint cadence, and the unigram decode prior. Against the saved 90.15 config the resolved config differs only in `max_steps`, `fp32_matmul_precision`, `log_interval`, `eval_interval` and `checkpoint_interval`. The plain arm has 14,233,681 parameters (1,317,632 in context processing) and the `block_read` arm 220,086,353, the difference being the 205,852,672-entry read-map table, the size of the VFE token-frame table.

Changes to the config block, with no change to library code: `DATA_SEED = 3` (the data order of the 34.48 run, which the launcher's old default of the model seed did not reproduce); `OVERRIDES = {"beta_attention_prior": "causal_alibi"}`, because the base prior is uniform causal with position carried by learned frames, so a copied prior would leave the baseline without any positional signal, and ALiBi is the standard zero-parameter choice (for the strict copy use `"causal"`); and `LR_SWEEP = (3e-4, 6e-4, 1e-3, 2e-3, 3e-3)` with `LR_SWEEP_STEPS = 6000`, because 6e-4 was chosen for a 30,000-step run. `PER_TYPE_TABLE` is left at the user's uncommitted `"block_read"`; the plain arm needs it set to `"none"`. Weight decay stays at the baseline default 0.1 on all matrices and tables, whereas the 34.48 run decays only the frames (0.1) and the MLPs (0.01), and it is not swept.

Checks, CPU only and nothing trained: the dry run resolves the config for both table arms, builds the plain model (14,233,681 parameters, matching the 90.15 run's recorded count) and runs a forward pass; `tests/test_baseline_20260928.py` and `tests/test_paper_arms_20260928.py` pass. Expected cost from the recorded 90.15 throughput (about 0.23 hours per 30,000 steps): roughly 1.2 hours for the 150,000-step plain run and 14 minutes for the five-point sweep; the `block_read` throughput has not been measured. One seed (6) is configured, so any gap to the 34.48 run is a single-seed comparison.
