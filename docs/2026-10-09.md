# Changes — October 9, 2026

## Log-cadence prototype-template diagnostics

The K=128 prototype-agent run `52.03_wikitext-103_K128_MinAgent_Proto_WorkVar_MeanField` collapsed to one template per layer before the first evaluation at step 10k, so the eval-cadence `diagnostics/prototype_templates.csv` recorded nothing of the onset (`docs/experiments/2026-10-09_prototype-K128-workvar-collapse.md`). Every persisted log or eval row now also writes `diagnostics/prototype_templates_train.csv`, with the same columns as the eval file, measured on the training batch through the forward that `model.diagnostics` already runs at that step (`vfe3/train.py`, the `do_csv` diagnostics block). The existing `_wrap_prototype_blocks` recorder wraps `forward_moments` for that one call, so the block inputs are exactly what the MLP receives under both `block_coordinates` settings, and no extra forward is added. The rows are pre-step and labeled `step + 1`, matching the `metrics.csv` row. The eval-cadence file on the fixed validation windows is unchanged.

A fresh `block_mlp_template_init='working_variance'` start now also writes `prototype_calibration.json` to the run directory, holding the target pull, the number of calibration windows, and each layer's measured working variance and chosen `lambda0`. Before this they went only to the logger.

The history figure `prototype_templates.png` (`vfe3/viz/feature_figures.py`, wired in `vfe3/viz/report.py`) now overlays both tables: the log-cadence training-batch rows as lines and the eval-cadence validation-window rows as markers, and it is drawn from either table alone when only one exists. Tests: `tests/test_prototype_train_logging_20261009.py`.
