## Prototype template codebook figure

`template_codebook.png` printed raw token ids, and its per-layer text columns overran each other. The ids came from `feature_figures._token_label`, which called the dataset decoder as `decode(int(token))`; `get_tiktoken_decoder` returns a decoder over a list of ids, so every call raised, was swallowed, and fell back to the id. ## Retirement of `phi_precond_mode` and the unused frame preconditioners

`phi_precond_mode` is removed from `VFE3Config`, at the author's request. No E-step reads it: the E-step frame update was already retired with `e_phi_lr`, and nothing in `vfe3/` called `precondition_phi_gradient`. The `pullback_group` M-step was its only reader, and that route required the value to equal the group's registered `pullback_capability`, which is `"pullback_per_block"` for `block_glk` and unset for every other group. So `none`, `clip`, `killing`, `killing_per_block` and `pullback` were either ignored or refused. On the shipped `block_glk` basis, which is Frobenius-orthonormal, the Killing modes were also only rescalings. The inverse metric is exactly (1/2K) I for `killing` (the center eigenvalue, lifted by the default `center_reg = 2K`, takes the same value) and (1/2d_h) I per block for `killing_per_block`. `clip` was a state-dependent scalar. Full `pullback` gives the same metric as `pullback_per_block` on `block_glk`, because for block-diagonal phi, d exp_phi(T_a) stays in the block of T_a, so every cross-block Frobenius entry is zero. A float64 CPU comparison at K=6 with H=1, 2, 3 agreed to 1.8e-15 or better.

`pullback_group` now dispatches the direction registered under `group.pullback_capability` (`stage_pullback_group_candidate`, `pullback_group_log_direction`, and `GaugeManifoldAdamW`, which lost the `phi_precond_mode` argument). The config check now refuses a group that has no capability. The `untied block_glk` requirement still refuses shared tying, which the two per-block-metric tying checks used to cover. In `vfe3/geometry/phi_preconditioner.py` the `_PRECOND` registry, `register_precond`, `get_precond`, `precondition_phi_gradient`, the six `_precond_*` rules, the Killing metric, its inverse builders and cache, `pullback_metric`, `pullback_metric_per_block`, the non-strict `_structure_constants` and the unused `_bch_chart_direction` are deleted. The module docstring now describes the per-block pullback direction it actually provides. Checkpoint parameter names are unchanged. Serialized configs that carry `phi_precond_mode` are not migrated, by the author's decision.

Launchers: the field is removed from `train_vfe3.py`, `ablation.py`, `scaling.py` and `parameter_optimization.py`. The author's working-tree edits to `train_vfe3.py`, `ablation.py` and `vfe3/config.py` are committed with this change. Tests: the dead-mode tests in `test_phi_preconditioner.py` (the legacy-golden, `none`, `clip`, Killing and ambient-pullback tests), the three `_bch_chart_direction` tests and the preconditioner-label test in `test_remediation_20260923_C.py`, the stale E-step `killing_per_block` forward test in `test_model.py`, and the Killing and per-block-metric tying tests in `test_gauge_tying_20261005.py` are removed. ## Confound controls for the per-type read-table comparison

The GL(K) v2 manuscript compares the evaluated K=128 realization (34.48 test perplexity) with a conventional transformer whose per-type read table nearly matches the frame table (55.10, `vfe3_runs/baselines/55.10_*`). That comparison leaves seven differences unisolated: where the per-type table acts (the frames read and write, the baseline table only reads), the optimizer, the positional mechanism (uniform causal prior with learned positional frames against ALiBi), the normalization layout (one shared post-norm against per-sublayer pre-norm), compute (the baseline trains about eleven times faster), the attention kernel (covariance-aware Gaussian KL against dot product), and seeds. This change adds the code for the controls; no run was launched.

`relational_routing="mean_distance"` (`vfe3/relational_scoring.projected_mean_distance_cost`) routes by half the squared distance of the projected means, the Gaussian KL with both projected covariances replaced by the identity, so it is the covariance-blind control for the routing kernel. It is nonnegative, so the cost bound applies unchanged, and like `noisy_query` it requires `attention_mode="projected_predictive"`. `vfe3/relational_scoring.routing_cost` maps routing names to cost functions for the posthoc interventions; `vfe3/gradients/relational.py` keeps its module-level dispatch.

`vfe3/baseline.py` gains `per_type_table="block_rw"`, which uses the frame-table-sized `(V, H, d, d)` table on both sides of attention as the realization uses its frames: the attention input is read through `exp(-X)` and the attention output written through `exp(X)`, block-diagonal on heads, identity at zero initialization. It also gains `norm_placement="post_shared"`, the realization's layout: one LayerNorm shared by every layer after the attention residual, the MLP residual on the normalized state, and no final normalization, which makes the context-processing parameter count exactly the realization's.

`paper_arms.py` now defaults to the 34.48 base (`k128_exp`), the new `base_protocol` budget (the base's own 150,000 updates and validation cadence), seeds `(6, 3), (23, 23), (54, 54)` and a baseline learning rate of 3e-3, the validation choice of the October 6 sweep; the 39.77 and 52.91 bases are kept and labeled as the earlier study. A baseline arm may declare `overrides`, and a protocol field among them is a declared difference. New arms, also listed in `paper_artifacts.py`: "Per-type read table, ALiBi (as run)" (the 55.10 configuration), its single-change variants with the realization's optimizer (Adam beta_2 0.999, no matrix decay, decay 0.1 on the table), with a read-and-write table, and with the shared post-norm, plus the VFE arms "Learned frames, ALiBi prior" and "Covariance-blind routing (mean distance)". With a causal-prior base, the existing "Per-type table of the frame table's size" row is the read table under the realization's prior. `TIER_A` (baseline controls and the compute-matched transformer) and `TIER_B` (evaluated replicates, identity frames, identity frames with an equal additive table, ALiBi realization, mean-distance routing) name the two launch sets; `CONFIG["arms"]` accepts either name. A dry run on the 34.48 base resolves every arm with only its declared changes; Under `base_protocol` the evaluated arm's replicate at the base run's own seed pair, (6, 3) from `provenance.json`, is the 34.48 run itself: `paper_arms.completed_run` returns it, so it is skipped in training, listed in the manifest, and read by the compute-matched rule. TIER_B then estimates 229 GPU-hours. The identity-frame arms also remove the positional frames, a coercion of `gauge_transport="off"`, so they change positions as well as frames.

Tests: `tests/test_confound_controls_20261007.py` (9 tests: the mean-distance cost against the identity-covariance KL and its independence of covariances, dispatch, a tiny-model forward and backward, `block_rw` identity at zero initialization, its inverse read and write and gradient, the post-norm count and gradient, the resolution of both tiers, and the reuse of the base run as the evaluated replicate). `tests/test_paper_arms_20260928.py` accounts for the new group and for the ALiBi arm being inapplicable on an ALiBi base, and its dry-run test selects every arm explicitly. ## Opus remediation of the October 7 audit, phase 2: numerics and correctness

The minimal-agent mean-field label-staleness diagnostic (`_label_staleness` in `vfe3/model/minimal_agent.py`) now replaces a non-factoring utterance covariance, a non-finite posterior mean or a non-factoring posterior query covariance with placeholders before its KL, and reports NaN for them. A failed float32 attempt therefore flags the call for the float64 retry instead of raising inside diagnostics (item 13). The old code raised on the audit's probe; the explicit diagnostics flag the audit also proposed was not added. The exact readout accumulates the between-source spread R centered per tile, two-pass within a tile, and merges tiles with Chan's pairwise update inside the online log-sum-exp (item 33). On the audit's offset-300 probe, float32 R is now 6.47e-7 against 6.36e-7 in float64, where the uncentered form gave -7.8e-3; the remaining 2 percent comes from the float32 rounding of r itself.

Under self-masking priors (`causal_noself`, `causal_alibi_noself`), the minimal agent no longer treats the forced (0, 0) entry as a record of the receiver's own snapshot: a receiver whose only admissible source is itself, under a prior that masks self elsewhere, receives zero head updates (item 51). Plain causal priors are unchanged.

`_loewner_adjoint` in `vfe3/geometry/retraction.py` evaluates the divided differences of pairs where both eigenvalues are active with cancellation-free closed forms: 1/(sqrt a + sqrt b), its inverse-square-root analogue, e^b expm1(a - b)/(a - b) and log1p((a - b)/b)/(a - b) (item 35). The float32 adjoint error on a near-isotropic spectrum fell from about 4e-4 to below 1e-5. Rows that `_certify_public_spd` rebuilds are now counted on device (`public_spd_repair_elements`) and reported in `realized_updates` (item 27). The repair bound itself is unchanged, because it is the size of the float32 eigenvalue error.

`validated_cholesky_solve`, `cholesky_qr2` and `apply_mu_trust_region` in `vfe3/numerics.py` now also run with autocast disabled, not only under the IEEE float32 matmul policy. They give bit-identical results inside a bf16 autocast region (item 26). The mean trust region clamps an overflowing whitened coordinate and takes an overflow-safe norm on both the diagonal and full paths, so a saturated step pins at the trust radius instead of vanishing (item 53); finite norms are unchanged. The diagonal Gaussian KL now evaluates its covariance term as x - log1p(x) outside the series band. The Laplace KL is regrouped exactly as [rho - 1 - log rho] + rho [exp(-u) - 1 + u], with series near zero (`x_minus_log1p` and `expm1_neg_plus` in `vfe3/families/base.py`, item 54). The median float32 relative error just outside the band fell from 2e-3 to 7.6e-6. Values away from equality change at roundoff level, so runs are not bit-identical to earlier ones on routes that evaluate these KLs.

`GaugeManifoldAdamW.step` now honors GradScaler's fused-path contract. On an overflow step (`found_inf`) it skips the manifold commit and leaves everything unmoved; otherwise it divides the manifold phi gradients by `grad_scale` before building the step (item 30). This was tested with a fused CPU AdamW; CUDA was not run. The finalize finite-difference gradient check probes `prior_bank.decode_mu_embed` under an untied prior-bank decode. It records the probed parameter, or the reason for a NaN, as `fd_gradient_probe` / `fd_gradient_nan_reason`, and a tied prior-bank decode has no decode-only parameter (item 18). `ablation._cell_is_current` now accepts a cell whose stored config fingerprint differs only because the config schema changed: it reloads the cell's `config.json` through the run-config loader and compares the re-derived fingerprint (item 21). Saved configs that carry `phi_precond_mode` still fail that loader until item 1 is decided. The eval-cadence diagnostics add `train_sample_seen_fraction`, min(1, sB/W), beside `generalization_gap_fixed` (item 43). `flatness_reference_statistics` forms the float32 inverse as the live producer does: the float64 inverse of the float32 exponential (item 46).

Not changed: item 39 (the repeated terminal validation pass). The reuse gate proves that the terminal pass would be identical before reusing it, and the audit puts the saving at about 0.3 percent of a run.

## Opus remediation of the October 7 audit, phase 3: decisions and design items

The author decided three things: retire `phi_precond_mode` as inert, keep run directories named by test perplexity, and implement the design items with any new behavior behind a toggle. `phi_precond_mode` is now in `_RETIRED_INERT_FIELDS` (item 1). New toggles, all defaulting to the previous behavior:

- `block_mlp_template_init` = "absolute" | "working_variance" and `block_mlp_template_init_pull` (default 0.09), items 14 and 15. Under "working_variance", a fresh `train()` start calibrates every prototype-agent layer in order, on `batch_size` training windows drawn by a private generator, so the data order and the global RNG streams are unchanged (`VFEModel.calibrate_prototype_templates`, `PrototypeAgentBlockMLP.calibrate_templates`). The template means are block-input means sampled from those windows, and lambda_0 = c(1 - p)/p, where c is the measured mean working variance, so the initial pull at uniform routing is p. Lambda sets both the pull and the routing temperature, so initial routing stays soft unless the input spread exceeds lambda_0. Routing selectivity at the launcher shape was not measured.
- `rope_space` = "frame" | "comparison", item 25. Under "comparison", no frame carries the rotation. `relational_score` instead rotates each token's projected query and key moments in the r-dimensional comparison space after the learned maps. The cost is invariant under a common orthogonal map, so each pair cost depends on positions only through j - i. This mode is limited to projected_predictive, the kernel readout and `rope_on_value=False`, which is routing-only rotation. The source-root recovery is disabled there, so a failing factor takes the float64 whole-tensor refactor. The two posthoc counterfactual scorers refuse it with NotApplicable.

Item 52 was not given a separate mechanism. The audit's fix for frozen Lie-algebra ALiBi, a per-head rotation applied after the projections, is the comparison-space rotation above. The `pos_phi="frozen"` documentation now says it routes on absolute position on the projected routes and points to that option.

`fisher_group` frame rows that fail the principal-strip certificate are no longer frozen (item 24). For those blocks, `uspace_ambient_gradient` and `uspace_chart_velocity`, under the new `offstrip=True` argument that only `fisher_group` passes, invert Psi_L(ad_{X^T}) and Psi_R(ad_X) in the eigenbasis of the chart block. This is exact wherever Psi is invertible, inside the 0.25 margin and beyond |Im lambda| = pi alike. A row is rejected only when that solve fails its gate: eigenvector condition, eigen-residual, min |Psi| and a real result. `pullback_group` keeps its own series route unchanged. Two tests in `tests/test_phi_fisher.py` that asserted the rejection now assert the same identities, and the trust bound, for the off-strip row. The chart-velocity linearization bound now scales with |v|^2, because that row sits near the exp singularity.

The `pullback_group` frame M-step now reaches every registered group (item 55). `so_n`, `block_so`, `block_co` and `block_glmc` register `pullback_per_block`, and `block_glk` no longer restricts the capability to per-head tying. When a generator acts on several blocks at once (a shared-tied frame, or so_n's one algebra across its irrep blocks), the per-block direction solves the metric as one full block, which is the exact Frobenius pullback. Against a dense pullback metric the direction agrees to a relative 1e-14 for every group. The dense product-residual check and the diagnostics now assemble the compact current element. The config gate "phase one accepts only untied block_glk" is removed. The block_glk d_head <= 12 guard, the group_log restriction to untied block_glk and the fisher_group restriction stay. A regression introduced in phase 2 was fixed. For a variance ratio below float32 resolution, x = (s - t)/t rounds to -1 and log1p returns -inf, which broke `test_prior_bank.py::test_decode_matches_reference_across_table_routes`. `ratio_minus_one_minus_log` now uses x - log1p(x) only for |x| < 1/2 and the two-log form beyond, with placeholder inputs in each branch so that neither the value nor the gradient picks up a non-finite term.

## Reduced-precision follow-ups: bf16 linear-decode logits and a step replay ladder

A CPU probe under bf16 autocast at the launcher's shapes (K=20, H=2, L=4, N=128, V=50257, batch 2) recorded the dtype of every matmul in one forward and backward. On every route at most 1.4 percent of matmul FLOPs ran in bf16, all of them in the coordinate block MLP. The decode and cross-entropy (57 to 79 percent of forward matmul FLOPs), the relational operators and scoring, the minimal-agent update, the prototype posteriors and the closed-form receiver all run with autocast off, most of them also pinned to IEEE fp32. The probe ran on CPU and counts FLOPs, not GPU time.

`decode_logits_amp` (default False) runs the linear decode's logits matmul x W^T under `amp_dtype` autocast and returns fp32 logits, so the bias, logsumexp and cross-entropy stay in fp32. It is read only with `decode_mode="linear"` and an `amp_dtype`, and when it is on the minimal-agent rule no longer reports `amp_dtype` inert. The prior-bank Gaussian decoders are not covered: their logits come from an expanded quadratic form that cancels, divided by `decode_tau`, and their a_v matmul is pinned to IEEE fp32 for its error certificate.

`matmul_precision_retry` (default False) addresses steps that fail under a reduced `fp32_matmul_precision`. When a training step raises before the optimizer has updated (a step pre-hook detects an update), `train()` drops the gradients, restores the CPU and CUDA RNG states and replays the step, forward and backward, one rung stricter on the ladder "medium" -> "high" -> "highest". A failure that persists at "highest" is raised with the earlier failures attached as notes, out-of-memory errors and failures after an update are never replayed, and the replay is not used with the fp16 GradScaler. Replayed steps are counted in `matmul_precision_replays` on each logged row and in `realized_updates` when the toggle is on. On the RTX 5090 "medium" took the same TF32 path as "high" in the October 4 measurement, so there the middle rung repeats the first.

Both toggles are in the `train_vfe3.py` config dictionary, off. Tests: four more in `tests/test_audit_20261007_mimo_tier.py` (ladder order and RNG replay, raising at "highest" and after an update, the bf16 logits matmul, a tiny linear-decode model).

## Logging- and eval-step cost

In the finished K=20 runs (`103.02_wikitext-103_K20_kernel`, `112.74_..._DiagChunk-tau=0.1`; batch 32, log every 500 steps, eval every 3,000) each 500-step window spends about 62 s in the CUDA-timed train step and a further 8.3 s outside it, flat from step 1,000 to 29,500; eval windows add about 26 s more. On CPU the real `train()` loop shows no gap between silent steps (a batch fetch is 0.15 ms); a log step adds about 0.3 s (`model.diagnostics` about 230 ms, group update statistics 42 ms, the rest under 20 ms). The suspected GPU-specific cost is the non-symmetric eigenvalue problem that `model.diagnostics` solves on every token's frame (B N = 4,096 matrices at batch 32, three calls), which CUDA PyTorch runs through MAGMA's hybrid `geev` one matrix at a time. Those calls (`per_head_gauge_invariants`, the self-loop spectral radius in `model.py` and `content_link_spectrum`, and the post-hoc triangle holonomy spectrum) now go through `metrics.eigvals_on_host`, which solves the same eigenproblem by LAPACK on the CPU (about 0.16 s for all three at batch 32) and returns to the input's device. This is inferred from the measured gap and the CUDA implementation path, not measured on the GPU.

To confirm it on the next GPU run, every `metrics.csv` row now carries `LOG_TIMING_COLUMNS`, each phase bracketed by a device synchronization: `log_diagnostics_ms`, `log_group_stats_ms`, `log_row_ms` on log rows, and `eval_validation_ms`, `eval_sample_ms`, `eval_val_diagnostics_ms`, `eval_best_and_maps_ms`, `eval_cadence_ms`, `eval_gap_train_ms` on eval rows (NaN otherwise).

One real eval through `train()` on CPU at the launcher's configuration (validation 7,654 windows at stride 32, 240 batches) measured 206 s for the validation pass, 189 s for the eval-cadence diagnostics, 5.5 s for the best-model save and attention maps, 0.8 s for the gap's train side and 0.07 s for validation diagnostics. The cadence cost is the fixed training-sample CE, which scores as many targets as the validation split (up to `TRAIN_SAMPLE_MAX_TARGETS = 262,144`) under the same stride-32 protocol, so every eval runs two full validation-sized passes. Shrinking that sample is a measurement-precision choice left to the user.

Tests: `tests/test_training_diagnostics_20260928.py` gains the timing-column and host-eigenvalue tests. Full CPU fast lane: 3,810 passed, 12 skipped, 0 failed.

At the user's direction the training-time fixed sample was reduced: `vfe3.train.TRAIN_SAMPLE_MAX_TARGETS` is now 32,768 targets (1,024 windows at stride 32) instead of 262,144, so on WikiText-103 the cap binds and the sample costs about an eighth of a validation pass per evaluation. The estimated standard error of its mean CE is a few hundredths of a nat (estimated, not measured); `train_sample_ce` and `generalization_gap_fixed` of earlier runs used the larger sample. ## RoPE for the paper arms and the conventional baseline

The K=128 paper base is to be rerun with comparison-space RoPE (`pos_phi="none"`, `pos_rotation="rope"`, `rope_space="comparison"`) and a prior-bank decode (`diagonal_chunked`, `expected_likelihood_chunked` or `full_chunked`). Resolving every arm of `paper_arms.py` against synthetic bases built from the 34.48 record with those settings showed that the decode modes needed nothing (the matched baseline already declares its linear decoder), while RoPE broke four arms through guards written for frame-space RoPE.

Comparison-space RoPE rotates each head's projected routing moments after the learned maps and is never folded into the frame (`VFEModel._rope_rotation` returns None), so `Omega_ij = U_i U_j^{-1}` is untouched. `vfe3/config.py` now applies the frame-RoPE rejection only under `rope_space="frame"` in three places: `gauge_transport="off"` (identity frames), `encode_mode="per_token_additive"` (the Omega = I capacity control) and the reference-coordinate requirements of `block_coordinates`/`decode_coordinates`. On a RoPE base the identity-frame arms therefore keep relative position, whereas on the learned-`pos_phi` base they also lost all position; the two are different ablations and the table text should say which one was run.

`vfe3/baseline.py` gains `pos_rotation` ("none" | "rope") and `rope_base`. Under RoPE each head's query and key are rotated by `R_i` from `vfe3.geometry.rope.build_rope_rotation` with the head width, the same frequencies the VFE uses in comparison space, so scores depend on position only through `j - i`. `BaselineConfig.matched_to` copies both fields from a RoPE base, and `paper_arms.BASELINE_PROTOCOL_FIELDS` checks them. The ALiBi confound (`_ALIBI`) now also sets `pos_rotation="none"`, so on a RoPE base it swaps the positional scheme instead of stacking ALiBi on RoPE (a no-op change on a base without RoPE). The intertwiner arm is reported inapplicable, not invalid, for a decode without a reference-coordinate reduction (`expected_likelihood_chunked`). `train_baseline.py` copies RoPE from a RoPE base and applies ALiBi (`POSITION_FALLBACK`) only to a base without RoPE; `OVERRIDES` is empty by default and still wins.

Tests: `tests/test_rope_paper_arms_20261007.py` (8 tests: the four frame controls accept comparison RoPE and reject frame RoPE, identity frames keep the comparison rotation, baseline RoPE scores are Toeplitz on a constant sequence, the baseline rotation equals the VFE's per head, and `matched_to` plus the arm check copy, flag and swap it). With the baseline, confound, paper-arms, RoPE and October 7 Opus-fix suites, 127 passed on CPU.

## p-RoPE fraction (`rope_fraction`)

With comparison-space RoPE several heads lock onto self (self-weight above 0.97: four of eight at step 3,000 with `rope_base=100`, two of eight with `rope_base=10000`; none in any learned-`pos_phi` run). Raising the base cannot reach the fastest pair, whose frequency is `base^0 = 1` radian per position at any base. The new toggle `rope_fraction` (default 1.0, RoPE unchanged) implements p-RoPE of Barbero et al. (ICLR 2025, arXiv:2410.06205): only the `floor(p d / 2)` fastest pairs of each block rotate, at their full-RoPE frequencies, and the slower pairs stay unrotated, a position-free subspace in which a head can match tokens by content at no positional cost. Their Gemma 2B runs found 0.75-RoPE at least as good as RoPE (Wikipedia validation perplexity 4.4414 against 4.4627). p-RoPE keeps the fastest pair rotated, so it does not by itself test the fastest-pair self-lock hypothesis; it gives every head an escape channel.

The fraction reaches every RoPE path through `vfe3.geometry.rope.build_rope_rotation(fraction=...)`: frame space (`VFEModel._rope_rotation`), comparison space (`RelationalOperators.comparison_rope_fraction`, read in `relational_score`) and the conventional baseline (`BaselineConfig.rope_fraction`, copied by `matched_to` and checked by `paper_arms`). The config rejects a fraction outside (0, 1] or one that rotates no pair of some block (p = 0 is NoPE, which is `pos_rotation="none"`). `train_vfe3.py` exposes `rope_fraction = 1.0`. Tests: six more in `tests/test_rope_paper_arms_20261007.py` (rotated pairs equal full RoPE and the rest are identity for p in {1, 0.75, 0.5, 0.2} at d = 10; the fraction reaches frame, comparison and baseline paths; comparison-space p-RoPE still routes on j - i only).

## Comparison-space RoPE on the minimal agent

`rope_space="comparison"` was restricted to the kernel readout because the rotation lived only in `relational_score`, while the minimal agent routes through its own exact source posterior. The minimal agent now takes it as a known record channel. Head h's record becomes `o = R_i S X_i - R_j T X_J + eps`; with isotropic channel noise this is the record `S X_i - R_{j-i} T X_J + eps'` of a source heard through `R_{j-i} = R_i^T R_j`. `vfe3/model/minimal_agent.py` computes every cost on the rotated moments `(R_i a_i, R_i A_i R_i^T)` and `(R_j b_j, R_j B_j R_j^T)`, so the labels depend on position only through `j - i`, and rotates the receiver statistics back to the record frame (`u -> R_i^T u`, `Lambda_bar`, the spread and the mean-field `Lambda` by `R_i^T (.) R_i`, `eta -> R_i^T eta`). This is the exact posterior of the rotated record: the gain `C_i S^T` is unchanged, and content arrives through `R_{j-i}` and is decoded by exact conditioning, so routing and content share one frame and no `rope_on_value` split arises. `RelationalOperators._minimal_agent_body` builds `R_i` with the configured base and p-RoPE fraction. The config now accepts comparison-space RoPE with `predictive_readout="minimal_agent"` (still `rope_on_value=False`); frame-space RoPE on the minimal agent still requires `rope_on_value=True`.

Tests: `tests/test_minimal_agent_rope_20261007.py` (10). Labels are Toeplitz on a constant sequence (exact head 0, whose ADF moments are the input moments, and every mean-field head). A common shift of all positions leaves every output unchanged, including the diagnostics, for p = 1 and 0.5 in both inference modes, which checks the rotate-back. `R = I` reproduces the unrotated readout to 1e-12. A one-source receiver matches direct Kalman conditioning on `S X_i - R_{j-i} T X_j + eps`. A tiny model trains a step in both modes with finite gradients. The minimal-agent, RoPE and October 7 audit suites pass on CPU.
