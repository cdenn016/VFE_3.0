# October 14, 2026

## One switch to the fully gauge-covariant model

`train_vfe3.py` has a launcher-level switch, `fully_gauge_covariant` (False by default; it is not a `VFE3Config` field). With it True the config dictionary is left as written, and at launch `vfe3.gauge_covariant.fully_gauge_covariant_overrides` changes only the keys that break gauge covariance, so that every entry of the `gauge_flags` of the pure-path report holds. The frames transport (`gauge_transport = "on"`). The family carries `g Sigma g^T`: `gaussian_full`, unless `gaussian_block` is chosen, with `diagonal_chunked` decoding moved to `full_chunked` and `decode_second_order` off. The block norm and MLP run in reference coordinates (`block_coordinates = "reference"`, `use_cg_coupling = False`), or stay local when the MLP is covariant on its own (`canonical_frame`, `gauge_gate`) under an equivariant norm. The decoder reads the reference moments (`decode_coordinates = "reference"`). No fixed-coordinate cap or trust region remains (`sigma_max`, `phi_mstep_max_matrix_norm`, `phi_frame_condition_max`, pullback and Fisher phi steps). The encoder is `per_token`, frame-space RoPE becomes `comparison`, and the self term uses the total KL (`lambda_alpha_mode = "state_dependent"`). Combinations with no covariant reading that keeps the chosen block are refused with the reason.

The switch does not touch the content links (the chart, the low-rank Lie-algebra edges `L_ij` and the latent-link settings), the routing, the readout, the predictive covariance, the learning rates or the numerics. After building the config the launcher re-derives the gauge flags (`gauge_covariance_failures`) and refuses the run if any is false. The overrides are logged and listed in the header of the run's `config.md`.

On the launcher as committed the switch sets `family = "gaussian_full"`, both coordinate fields to `"reference"`, `sigma_max = None` and `lambda_alpha_mode = "state_dependent"`. `tests/test_fully_gauge_covariant_20261014.py` (14 cases, config level, no model built) checks ten non-covariant launcher variants. Among them are exponential and low-rank content links, comparison and frame RoPE, pullback phi steps, no block MLP and a `gauge_gate` MLP. Each is off the gauge facet before the overrides and on it after, with the content-link and other non-gauge keys unchanged. A covariant configuration gets no overrides, the two unsupported block combinations are refused, and the switch defaults off. No training run was made with the switch on.

The same switch is in `ablation.py` (`fully_gauge_covariant`, False by default, next to `BASELINE_CONFIG`). With it True the overrides are applied to the baseline in `_resolved_sweep_baseline`, before any arm, so sweep validation, labels, parameter matching and every cell read the covariant baseline. An arm that breaks covariance again is refused at startup by `validate_sweeps` and, if it is reached, recorded as a config error by `run_single`. The switch is a declarative name, so flipping it does not change the runner-source hash; cells still recompute because their resolved config changes. A test in the same file covers the baseline overrides, the refusal of a breaking arm, cell construction and the default.
