# Changes — October 2, 2026

## Chunk relational diagnostic eigensolver batches

`VFEModel._relational_diagnostics` now calls the existing `safe_eigvalsh` helper for stacked projected query/key covariance matrices. The helper chunks batches above 16,384 matrices, avoiding cuSOLVER’s small-matrix batched eigensolver call limit while preserving the eigenvalues.

Validation: model source parses and a tiny CPU comparison matches `torch.linalg.eigvalsh`. No CUDA reproduction or training was run.

## projected_gradient receiver laws and updates

Implemented the projected_gradient fixes derived in `Research/manuscripts/Attention/projected_gradient.tex` and the route-specific findings of `docs/audits/projected-gradient-pr30-32-audit-2026-10-01.md`. The PR #30 receiver remains selectable unchanged.

Three configuration fields were added. `relational_receiver_law` selects `"channel_likelihood"` (default) or `"ambient_alignment"`. The channel law scores the receiver's partial law $O_h^\top\xi_i$ against the sender's $d$-dimensional message $T_h\xi_j$ as an expected likelihood with channel noise $\nu I_d$, pooling $d\times d$ blocks and lifting them through the tied measurement $P_h=O_h^\top$. It counts the receiver entropy once ($c=\alpha$), its minimizer is the exact tempered Gaussian posterior, and directions no head observes keep the prior. The ambient law is the PR #30 energy, with $c=\alpha+\sum_h\lambda_h$ and zero-mean pinning of each head's unwritten coordinates. `relational_receiver_update` selects `"closed_form"` (default) or `"euler"`. The closed form applies the exact frozen-context natural-parameter update $J^+=(1-\rho)\Sigma^{-1}+\rho\Lambda/c$, $h^+=(1-\rho)\Sigma^{-1}\mu+\rho\eta/c$ with `relational_receiver_damping` $\rho\in(0,1]$. That is the exact Fisher flow for `gaussian_full`, and the restricted minimizer at $\rho=1$ for the diagonal family. `"euler"` is the PR #30 step. Serialized configs without these fields reload as `ambient_alignment` with `euler`, so saved PR #30 runs keep their receiver. Under `closed_form`, `inactive_fields` reports the E-step rates and trust radii as inert; under `euler` it reports the damping as inert.

Audit fixes on this route follow:

- **F4.** `n_e_steps=0` is rejected for projected_gradient.
- **F4, F13.** The episode captures (receiver cost after, repair count, displacement) are now written after the E-step loop in `e_step`. They exist for every iteration count, the repair window opens before the context build so routing-score recoveries are counted, and the displacement covers the whole episode.
- **F3.** New diagnostics `relational_receiver_mean_cost_delta`, `relational_receiver_covariance_cost_delta` and `relational_receiver_target_distance_ratio` (with `val_` columns) separate the mean and covariance parts of the frozen energy and measure the distance to $\mu^\star=\Lambda^{-1}\eta$.
- **F6.** Receiving-law factorizations use `cholesky_ex` with a counted float64 retry.
- **F7a.** `full_link_gradients` no longer rounds its force to a half-precision incoming mean.
- **F9.** The Q/K/V trace accepts the configured `n_e_steps` and attaches the receiver costs.
- **F14.** `RelationalOperators` accepts any finite real `receiver_noise`, matching config validation.
- **Artifacts.** Fields record the receiver law, update and damping.
- **Docs.** README documents the fields.

`lambda_alpha > 0` is required under `channel_likelihood`, because the prior divergence carries the only entropy term.

## Decode temperature and Cholesky jitter selectors retired

Two more config fields were removed by user decision. `decode_temperature_learned` is gone: `prior_bank.decode_log_scale` keeps its name, so the checkpoint layout is unchanged, but `VFEModel` always freezes it (requires_grad False), so it joins no optimizer group and tau_eff = decode_tau * exp(-clamp(decode_log_scale, -3, 3)) stays at its initialized or loaded value. This is the former False behavior made unconditional. `safe_cholesky_jitter_mode` is gone as well, together with the process-global setter and getter and the `jitter_mode` keyword in `vfe3/numerics.py`: `safe_cholesky` always uses the relative ridge eps * 10^t * max(1, |diagonal mean|), whose numerics are unchanged. Standalone callers that formerly took the process default "absolute" now get the relative ridge; the two agree whenever the diagonal mean is at most one.

Loader rules (`_migrate_retired_fields`, both keys in `RETIRED_CONFIG_KEYS`): a saved `decode_temperature_learned` loads with either boolean value, because the saved `decode_log_scale` is restored from the weights and held frozen, so evaluation replays the saved temperature exactly. A saved `safe_cholesky_jitter_mode='relative'` loads; `'absolute'` loads only for a diagonal family, which never factors a dense covariance, and is refused as retired otherwise. The `m_decode_lr` migration still reads the historical temperature key, with historical default True.

Resume guard (`run_artifacts._drop_retired_decode_temperature`): a checkpoint whose optimizer manifest groups `prior_bank.decode_log_scale` is checked before manifest validation. If the temperature's saved AdamW slot is populated, the run trained it, and resume is refused with a "retired learned decode temperature" message instead of a manifest mismatch; loading weights without an optimizer still works. If the slot is empty (for example under linear decode, whose readout discards tau_eff), the entry is dropped and the optimizer state loads exactly. Both cases were checked against real checkpoints written by `2adaafc` and are covered by tests.

Parameter accounting (`run_resources.frozen_parameter_names`) now lists `decode_log_scale` as frozen unless a historical record carries `decode_temperature_learned=True`; `paper/runs.py` reads that historical key with default False, so a run predating the field is counted with a frozen temperature (one scalar).

## One transport domain radius; exponential precision policy retired

By user decision the scattered norm bounds on the transport matrix exponential were unified. `transport_chart_max_norm` is now a required positive finite float with default 20.0, the radius of the former Frobenius clamp, and it is always fail-closed: `stable_matrix_exp_pair` and `_stable_compact_glk_exp_pair` raise `ValueError` when the raw Lie-algebra matrix of any frame has ||M||_F above it or a nonfinite norm, and otherwise return exp(M) itself. The surrogate clamp (`TRANSPORT_CLAMP_MAX_NORM`, which rescaled M to ||M||_F = 20 and returned exp(M * scale)), its `clamp_monitor` keyword, the `_CLAMP_SURROGATE_WARNED` latch, the `transport_clamp_monitor` field, `train._warn_phi_transport_clamp` with its `_PHI_CLAMP_WARNED` latch, and the clamp-fraction diagnostics (`phi_exp_clamp_frac`, `phi_exp_scale_min`, their `val_` and never-produced `pos_` columns, and the "Exponential chart guard" panel of the geometry-health figure) are deleted. `metrics.phi_chart_statistics` and `metrics.flatness_reference_statistics` no longer emulate the clamp; they exponentiate the unscaled matrix, which is what the transport now does. The chart radius applies to the skew-symmetric so_n towers as well. Their exponentials are orthogonal, so the bound is not a conditioning guard there, but an embedded norm above 20 means runaway coordinates rather than a conditioning problem: exp on SO(n) is injective only below spectral norm pi (a single-plane rotation reaches it at Frobenius norm pi sqrt 2, about 4.4), so with few heads such a frame has already wrapped around, and failing closed flags it instead of silently wrapping; this also keeps the user launcher's current behavior, which already applied its chart bound of 18 to every group.

`phi_mstep_max_matrix_norm` stays a separate optimizer interior radius with its None semantics, and construction now requires it to be strictly below `transport_chart_max_norm` when set. The manifold phi-policy validator (pullback_group and fisher_group) previously required an explicit chart with factor radius < chart < 20; it now requires factor radius < `transport_chart_max_norm`, where the factor radius is `phi_mstep_max_matrix_norm` or 5.0, so the default chart of 20 admits those routes.

`exp_fp64_norm_threshold` is deleted together with `e_step._EXP_FP64_NORM_THRESHOLD`, every threshold keyword in `transport.py`, `e_step.py` and `model.py`, and the low-level default of 5.0. The exponential is now evaluated at the storage precision (float32, or float64 for a float64 input; previously a float64 input below the threshold was exponentiated in float32 and cast back). The condition-certified float64 rebuild of the frame pair is unconditional: `frame_pair_fp64_escalation`, `set_frame_pair_fp64_escalation`, `frame_pair_fp64_escalation()` and the `_FRAME_PAIR_FP64_ESCALATION` switch are removed, and every float32 producer call certifies max kappa_F(U) eps_32 <= 1e-4 inside its existing single inverse read and rebuilds the call's pair in float64 when the certificate fails. The escalation counter and its run-artifact field are unchanged.

Before deleting the norm trigger its reach was checked. Only `stable_matrix_exp_pair` (dense `compute_transport_operators` and the factored dense-vertex route of `build_factored_transport`, including its right positional factor) and `_stable_compact_glk_exp_pair` (the compact block_glk route and its right factor) ever read the threshold. Every production frame is built through one of them: the shared flat transport of `_build_shared_flat_transport`, hence the relational routing and value frames of `_relational_frames`, the canonical_frame block-MLP frame, the reference frame captured for `decode_coordinates='reference'`, the diagnostic transports, and the learned positional frame exp(Y) through `right_phi`, whose composed pair (U E, E^-1 U^-1) is certified jointly. All of these build the inverse, so all are certified; `only_forward=True`, which skips certification, has no caller. The RoPE rotation is built from cosines and sines, never from a matrix exponential, and an escalated float64 pair still meets it re-orthogonalized at float64 (`_rope_at_frame_precision`). The phi M-step group exponentials (`gauge_optim` candidate and pullback elements, the phi preconditioner, `phi_fisher`) and the head-mixer exponential call `torch.linalg.matrix_exp` directly and never read the threshold, so they are unchanged by this retirement.

Loader rules (`_migrate_retired_fields`, keys in `RETIRED_CONFIG_KEYS` and so in `legacy_config.MIGRATED_HISTORICAL_KEYS`): `transport_clamp_monitor` loads with any value and is dropped, since it only toggled a warning. `exp_fp64_norm_threshold` loads with any value and is dropped. Whenever the saved threshold is at least the chart radius in effect (the shipped 20 with a chart of 18 or 20, and the 20 with no chart, where the clamp capped every frame at 20) it never changed a result: each per-block norm is at most the whole-frame norm, which the chart or clamp bounded by the radius, so the float64 interior was reachable only at exact equality. A saved threshold below the radius, such as the 15 in some `zzzzz.py` presets, did compute the exponentials of frames with a block norm in [threshold, radius] at float64 before rounding to float32 storage, so such a run replays with float32 rounding differences on those frames. `frame_pair_fp64_escalation` loads with either value: True is now the only behavior, and a saved False only lacked the float64 rebuild of pairs whose float32 certificate failed, so replaying it adds precision exactly where the float32 pair was not mutually inverse. A saved `transport_chart_max_norm=None` loads as 20.0, the old clamp radius. Runs that relied on the surrogate clamp, with any frame whose ||M||_F exceeded 20, now raise at the first transport build instead of exponentiating a rescaled matrix. A saved `phi_mstep_max_matrix_norm` at or above the loaded chart radius is refused at construction.

Launchers: the `exp_fp64_norm_threshold` and `transport_clamp_monitor` lines were removed from `train_vfe3.py`, `ablation.py`, `scaling.py`, `parameter_optimization.py` and `zzzzz.py` (edited as text, since it does not parse); no other launcher value changed. `zzzzz.py` still sets `transport_chart_max_norm = None` in four presets, which construction now rejects; they were left as they are. `agent_tooling/precision_phase0.py` lost its frame-pair escalation profiling row. `paper/tables.py` no longer lists `exp_fp64_norm_threshold` among the exponential keys, and in `run_artifacts` the `no_transport_exponential_clipping` gauge flag is constant True and `transport_chart_max_norm` is always a float. The README has no rows for these fields.

## Rounding-level numerical selectors hardcoded; absolute LR floor retired

By user decision five numerical-policy fields were removed from `VFE3Config`; in each case the surviving arithmetic is the one that avoids a cancellation or a full-vocabulary float64 recompute, and the retired alternative computed the same mathematical quantity.

`decode_ce_stable_reduction` is gone and the fused nonlinear CE (`decode_ce_diagonal_chunked`, `decode_ce_full_chunked`, `decode_ce_expected_likelihood_chunked`, `decode_ce_family_chunked`) always reduces each vocabulary chunk relative to its detached maximum: `_decode_ce_chunk_summaries` returns L_c = logsumexp_v(s_v - m_c), the centered target and m_c, and `_decode_ce_combine_summaries` combines them relative to M = max_c m_c. The CE is invariant to the shift, so this is the former True branch made unconditional; the uncentered branch (absolute logsumexp minus absolute target, which cancels at large scores) and the family kernel's masking that only it needed are deleted. Linear CE keeps its own reduction.

`decode_ranking_refinement` is gone and the ranking guard (`decode_ranking_fp64_escalation=True`) always resolves an uncertain float32 ranking by candidate refinement (`_refined_candidate_decode`), which reproduces the argmax of a complete float64 decode. The former "full" path is deleted, not kept privately: `_promoted_expanded_decode`, `_chunk_ranking_summary`, `_streamed_final_ranking_uncertain` and `_DECODE_RANKING_REFINEMENTS` are removed, and the fused CE kernels no longer build ranking certificates. Under "full" the guard also promoted the training CE to float64 whenever any row's ranking interval overlapped; the CE now streams in float32 under the guard exactly as with the guard off. This matters for launchers that set `decode_ranking_fp64_escalation=True` without a refinement (`ablation.py`, `scaling.py`, `parameter_optimization.py` and one `zzzzz.py` preset ran the former default "full"): their training CE on near-tie batches now stays in float32. The refinement test now uses a float64 copy of the bank as its oracle.

`decode_ce_checkpoint` keeps the public values "auto" and "auto_aggregate". The forced "always" and "never" policies remain on `PriorBank` (the constructor, attribute and `_decode_ce_should_checkpoint` are unchanged) for tests, but `VFE3Config` refuses them. `paper_arms.py` set "always" for the word-level Gaussian arm; it now sets "auto_aggregate", whose whole-vocabulary estimate exceeds the 2 GiB threshold at the word vocabulary and therefore checkpoints every chunk as "always" did. This is the one launcher value changed, because the old value no longer constructs.

`min_lr` is gone: it was 0 on every entry point, and the scheduler floor is now `min_lr_frac * base` per group (`train._floor_lr_lambdas`). `run_artifacts._scheduler_metadata` no longer records an `absolute_floor`; `effective_floor` is `min_lr_frac * base` (0 for a frozen group). `paper/figures.py` and `paper/tables.py` no longer read the key, and the paper-arm baseline protocol map drops it. The conventional baseline trains through the same scheduler, so `BaselineConfig.min_lr` would otherwise be silently ignored: the field stays (saved baseline configs carry it) but construction now refuses any nonzero value, and `baseline.MATCHED_FIELDS` no longer copies it from the VFE config.

`predictive_covariance_centering` is gone and `RelationalOperators.predictive_covariance_update` always shifts the source means by token 0's, xi_j -> xi_j - xi_0, before forming the between-source spread sum_j beta_ij n_j n_j^T - n_bar_i n_bar_i^T. The spread is invariant under a common shift because every beta row sums to 1, the shift does not reach the mean readout, and it is causal because token 0 lies in every causal row's support. The constructor keyword, its validation and the `model.py` plumbing are removed.

Loader rules (`_migrate_retired_fields`; all four removed keys are in `RETIRED_CONFIG_KEYS`, hence in `legacy_config.MIGRATED_HISTORICAL_KEYS`): `decode_ce_stable_reduction` and `predictive_covariance_centering` load with either boolean value and are dropped, and a non-boolean is refused. A saved False replays with rounding-level differences only (centered CE reduction; mean-shifted spread). `decode_ranking_refinement` loads as "candidates" or "full" and is dropped; a saved "full" replays with the training CE in float32 instead of a float64 promotion on near-tie batches, a precision-only difference, and the logits argmax is the same. A saved `decode_ce_checkpoint` of "always" or "never" loads as "auto"; this changes only memory and backward recomputation. `min_lr` loads at 0 and is dropped; any nonzero value (or a bool) is refused as retired, because it changed the LR schedule.

## State-dependent self-coupling on projected_gradient; predictive knobs inactive there

`lambda_alpha_mode` in `{"state_dependent", "state_dependent_per_coord"}` is now accepted under `attention_mode="projected_gradient"`. The derivation is the new section "Profiled state-dependent self-coupling" of `Research/manuscripts/Attention/projected_gradient.tex`. Because $\alpha^\star(D)=c_0/(b_0+D)$ minimizes $\alpha D+b_0\alpha-c_0\log\alpha$, the receiver energy profiles to $E=c_0\log(b_0+D)+G$ with $D=\mathrm{KL}(q_i\Vert p_i)$ against the layer prior and $G$ the energy at $\alpha=0$. Its exact gradient is $\alpha^\star(q)\nabla D+\nabla G$ (envelope theorem), which is the existing quadratic-family force with $\alpha$ frozen at the current state. The receiver recomputes $\alpha^\star$ at every E-step iteration. Under `euler` that gives the exact profiled force. Under `closed_form` the frozen-$\alpha$ minimizer is a majorize-minimize step, because the concavity of the logarithm puts $E$ below its tangent majorizer, so $E$ does not increase at damping 1. At damping $\rho<1$ descent is proved for `gaussian_full`, where the frozen energy is $c\,\mathrm{KL}(q\Vert q^\star)$ and the natural-parameter segment decreases it. It is not guaranteed for `gaussian_diagonal`: the nonuniform diagonal mean contraction can raise the dense quadratic, and an explicit instance raises the frozen energy from 1.500 to 2.503 at $\rho=1/2$. That instance holds for constant $\alpha$ as well, so it is a property of the existing diagonal damping.

Per coordinate, on the diagonal family with a diagonal prior, the KL separates over local coordinates. The frozen prior term becomes $\mathrm{diag}(\alpha_k/p_k)$ and the entropy weight becomes the vector $c_k=\alpha_k+m$, where $m=\sum_h\lambda_h$ under ambient alignment and $0$ under channel likelihood. The diagonal-family energy still separates in the variances, so the closed form $s_k=c_k/\Lambda_{kk}$, $\mu=\Lambda^{-1}\eta$ remains exact. Euler and closed form are both implemented for it. `state_dependent_per_coord` with `gaussian_full` stays rejected on this route. The manuscript derives an exact full-family closed form, $\Sigma^{-1}=\tilde U\,\mathrm{diag}(d_k/c_k)\tilde U^\top$ from the unit-upper factorization $\Lambda=\tilde U\,\mathrm{diag}(d)\tilde U^\top$ that matches the code's ordered conditional KL, and checks it numerically at $K=4$, but it is not implemented.

Code: `vfe3/gradients/full_link.py` adds `SelfCouplingProfile` (coupling-only $\Lambda$, $\eta$, mass, layer prior and $b_0$, $c_0$) as an optional `FullLinkContext.profile`, `self_coupling_divergence` (exact, unclamped KL, per token or per coordinate), and `full_link_context_at` (freezes $\alpha^\star$ at a state; returns a constant-$\alpha$ context unchanged). `build_full_link_context` takes `lambda_alpha_mode`, `b0` and `c0`. `full_link_gradients`, `full_link_minimizer` and `full_link_cost_parts` accept per-coordinate entropy weights on the diagonal family. `full_link_cost` returns the profiled energy for a profiled context, so `relational_receiver_cost_before/after` report it. `vfe3/inference/e_step.py` threads `b0` and `c0`, refreshes the context per iteration, and evaluates the episode cost parts on the context frozen at each reported state. `vfe3/model/block.py` passes `cfg.b0` and `cfg.c0`. The gauge-equivariance witness in `vfe3/viz/extract.py` uses $\alpha^\star=c_0/b_0$, since its prior equals the snapshot and $D=0$ there. $\alpha^\star$ keeps its autograd graph, because the unrolled outer derivative of the force map needs $d\alpha^\star/d\theta$.

Config (`vfe3/config.py`): under projected_gradient, `predictive_covariance="moment_matched"` and `attention_residual=True` no longer raise. Both are marked inactive together with `predictive_covariance_floor` as read only by projected_predictive, and `VFEModel` passes them to the operators only on the predictive readout. The positivity rules on `lambda_alpha` for the gradient route apply only to constant $\alpha$. `lambda_alpha` is marked inactive under a state-dependent mode. `relational_routing="noisy_query"` remains rejected on projected_gradient. It is a different routing cost that the full-link context does not implement (`build_full_link_context` requires `gaussian_kl`), not a knob without meaning there. `block_coordinates="reference"` also remains restricted to projected_predictive.
