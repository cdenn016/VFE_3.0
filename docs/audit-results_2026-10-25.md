## Findings requiring the earliest attention

F01 is at `vfe3/model/cue_result_memory.py:185-204`, `296-312`, and the tile merge/returned-weight paths. It normalizes by subtracting absolute log evidence after that evidence has already lost its small log-sum increment. With two identical components, a one-dimensional record of 10,000, unit record/component variances, and identity regression, the mathematically normalized answer has weights one half, mean 5,000, and variance 1.5. Both float32 kernels instead return total mass two, mean 10,000, and covariance 50,000,004 in one tile. One-component tiles return covariance three. This is an admissible finite-input failure shared by the current route's normalization code, not evidence that a current training record reached it. Carry a row maximum and scaled positive mass separately through both accumulation and merging; changing only the local softmax is insufficient. The returned regime weights need the same stable normalization. See [probes_initial.json](audits/ultradeep-2026-10-25/probes_initial.json) and [probes_config_cg.json](audits/ultradeep-2026-10-25/probes_config_cg.json).

F02 is at `cue_result_memory.py:292-299`. For rank one with F=I+UV^T=0, posterior cue variance one half, and Q=exp(-25), the expression `q + p + cross + quad` loses Q before cancellation. It returns zero where dense regression preserves 1.3887943746404563e-11. The construction embeds in one coordinate at the active rank two. Add Q after the regression variance and recompute cancellation-prone rows using a positive sum of squares or higher precision; adding Q last alone does not prove the remaining expansion accurate. The result should preserve the specified positive noise, rather than acquire an unrelated floor. The same receipt contains the exact fixture.

F03 and F17 arise at `vfe3/run_resources.py:235-250`. The state-dict interface has neither a complete parameter/buffer distinction nor a shared-parameter identity manifest. The tied-bank fixture has 264 bank parameters; three layer names produce 792 counted entries even though `named_parameters()` yields the bank once. Training `resources.json` is correct on this fixture; posthoc accounting and paper fallback paths can be wrong. A saved parameter/alias manifest or validated topology can solve both accounting problems. Storage-pointer deduplication alone is insufficient because the existing background snapshots already copy tied aliases independently. Preserve all checkpoint keys. The separate count of parameters read per token needs its own definition for repeated layer access. Evidence: [probes_contracts_followup.json](audits/ultradeep-2026-10-25/probes_contracts_followup.json).

F04 is the import-time `torch.set_default_dtype(torch.float64)` at `tests/test_local_learner_20261021.py:17`. Collection runs before tests, and the shared fixtures do not reset this global. A worker that collects the module can silently exercise other modules in float64. The focused pytest invocations here did not collect that file; a separate process demonstrated the mutation. Prefer explicit dtype construction or a function-scoped restoring fixture. This has direct relevance to interpreting broad-suite evidence for float32 numerical behavior.

F05 is the `_version` read at `vfe3/contracts.py:193`, reached through the repeated-token compact transport gather only when the target-scored model path enables factor reuse. `model.eval()` with `model(x, targets=y)` inside `torch.inference_mode()` fails for `[1,1,2]`; the same call with `[1,2,3]` succeeds. Both no-grad controls and both logits-only controls succeed. Skip the gathered-row certificate for inference tensors and use the existing full validation path, or supply an inference-compatible certificate. The repository evaluator uses no-grad, so this is a model API failure rather than a demonstrated launcher crash.

F06 spans `vfe3/run_artifacts.py:2986-2996` and `vfe3/train.py:5766-5796`. Saved divergence state is passed back through the artifacts object only. `artifacts=None`, including supported `RUN_ROOT=None`, restores weights and optimizer but discards the loss monitor and skip counters. In the normally generated tiny checkpoint fixture, the saved loss EMA is 1.241938; the continued threshold is 2.241938 and a 12.472694-nat loss is rejected when artifacts exist. Disabling artifacts resets warmup, removes the threshold, and accepts that same loss. Restore this state through an artifact-independent resume record. The fixture shortens monitor warmup and adds a controlled loss offset; it establishes the policy discrepancy, not corpus divergence. Evidence: [probe-resume-monitor.log](audits/ultradeep-2026-10-25/probe-resume-monitor.log).

F07 is at `run_artifacts.py:5233-5262`. The best-file publisher correctly retains the old best after a persistent ordinary Windows lock. The validation-only finalizer ignores the failed publication and reports the minimum observed score as the primary selected score. A fixture with an earlier best of 20 and an improving terminal score of 18 emits primary 18, best 20, old best step one, and a successful summary. The raw terminal checkpoint remains available; the defect is the contradictory selection handoff. Either refuse successful finalization or explicitly report the retained selected score and qualify the unpublished terminal score. Evidence: [probe-locked-terminal-selection.log](audits/ultradeep-2026-10-25/probe-locked-terminal-selection.log).

F08 concerns `local_learner_test.py:136-139`, `175-180`, and `243-247`. A completed result is identified only by arm, dimension, and seed; its record omits most effective settings. Editing a learning rate or schedule in the advertised click-to-run workflow can silently reuse a previous result. The current B-to-S WIP uses a different filename and is not itself this collision. Persist the effective arm settings, data/protocol identity, and source identity, and compare them before reuse. F09 is the analogous artifact-labeling risk in `vfe3/semantics/multiseed.py:206-213`: a checkpoint override loads different weights while retaining saved semantic metrics, then labels the aggregate with the new checkpoint. Require agreement or record separate analysis and stability checkpoints. Both are source-traced; existing result collections were not audited for impact.

F10 is at `vfe3/posthoc/feature_probes.py:145-213`. Per-layer wrapping assumes different bank objects. A tied bank receives nested wrappers, then cleanup deletes the same instance method twice. The empty-loader reproduction isolates the cleanup AttributeError; source tracing establishes that nonempty calls also attribute one invocation to multiple layers. Install one wrapper per distinct bank, retain actual layer-call attribution, and restore once. The end-of-run caller catches the exception and loses the feature report. This affects tied `prototype_agents`, not the current cue/result selector.

F11 is the subtractive small eigenvalue in `vfe3/geometry/phi_fisher.py:151-160`. At small positive whitened mean norm, it rounds to zero, produces an infinite condition certificate, and makes the actual chart optimizer reject an otherwise finite direction. The probe at means 1e-8 and 1e-9 raises `FloatingPointError`; exact zero and 1e-6 controls produce the expected small finite step. The supported trigger requires the stabilizer completion and chart retraction of the optional Fisher frame optimizer. Rationalize the small positive root and separate deliberate conditioning policy from diagnostic cancellation. The active AdamW frame path is unaffected. Evidence: [probe_fisher.json](audits/ultradeep-2026-10-25/probe_fisher.json).

## Other conditional defects and their limits

F12 is an `elif n_layers == 1` at `vfe3/config.py:2751` that prevents subsequent block-mode inactivity checks. The constructor still discards activation for the statistical memory modes, but the sweep validator can no longer see that it is inert. Make singleton tying detection independent of mode detection. F16 is the separate missing per-type hidden-bias table in `scaling.py:639-668`; the preview undercounts it, while completed scaling results retain the actual model count. Neither finding alleges a wrong result from the current frame-capacity experiment.

F13 and F14 are separate CG problems. `vfe3/model/cg_coupling.py:216-224` retains dtype-converted constants created under inference mode; a later gradient call cannot save them for backward. At `239-243`, the zero-weight no-grad shortcut returns the input covariance before applying the delta-full floor, whereas the ordinary path adds that floor at `305-309`. Both have direct small module reproductions. The current launcher disables CG. The direct differentiable-temperature API also has an inference-created constant cache failure at `vfe3/free_energy.py:93-104`, but the standard stack applies its learnable temperature after a fresh constant product; that API extension is documented with F13 and is not counted as another live defect.

F15 is at `cue_result_memory.py:243-255`. The dense kernel tiles components but passes every token to every tile. Once the estimate for one component across all tokens exceeds the configured budget, reducing the budget has no further effect. The instrumented example requests 96 bytes and each component call has an estimated size of 768 bytes. The kernel also has no per-tile checkpoint to suppress retained dense intermediates during backward. These are structural facts; no allocator peak was measured. The current launcher uses the diagonal kernel, which already has token tiling and checkpointing. Add those protections to the supported dense path without changing its posterior semantics.

F18 is confined to a fixed-context diagnostic interface, `vfe3/gradients/full_link.py:600-607`. For per-coordinate c, the scalar cost reduces log variances before weighting them, unlike the analytic force and `full_link_cost_parts`. It raises for N=3,K=2 and returns 2.312360796 instead of 1.054814121 for N=1,K=2. The production profiled context takes a different branch and is not shown affected. Apply the coordinate weights before the reduction. Evidence: [probe_full_link_oracle.json](audits/ultradeep-2026-10-25/probe_full_link_oracle.json).

F19 is at `vfe3/local_learner/learners.py:152-159`. With W=Szx(Sxx+rho I)^(-1), the shortcut Q=Szz-W Szx^T equals the true expected residual covariance plus rho W W^T. The scalar ridge-one fixture gives 1.5 instead of 1.25 and raises the conditional noise objective. The default ridge is 1e-6, so a material effect on recorded runs has not been shown. Compute the full residual expression, or explicitly define and test a different Q-dependent penalized objective if that is intended.

F20 is a rounding-sized prefix-independence defect in the minimal-agent wrapper at `vfe3/model/relational_operators.py:1425-1449`. A valid ill-conditioned suffix changes the whole call's precision branch, replacing healthy prefix outputs too. The raw prefix is bitwise identical while the returned prefix changes by 5.96e-8. No material information leakage, perplexity effect, or amplification was established. Replace only affected receivers or choose input-independent precision. Evidence: [gauge-probe-suffix.json](audits/ultradeep-2026-10-25/gauge-probe-suffix.json).

F21 and F22 require extreme finite values. The trust scaling at `vfe3/geometry/retraction.py:660-663,754-756` squares float32 tangents until the norm overflows; finite entries then scale to zero. At magnitude 2e19, both small covariance retractions return identity rather than the representable bounded step 2.02811498 times identity. An overflow-safe norm fixes the silent loss of direction. The optional expected-likelihood kernel at `vfe3/kernels/_expected_likelihood_triton.py:120-128` allows its first all-negative-infinite score tile to form `-inf - -inf`. A later finite target cannot recover the online sum. A 65-class CPU-interpreter fixture produces NaN instead of a forward CE of zero; compiled CUDA and backward behavior remain untested. The active diagonal KL decoder already has the corresponding prefix guard. Evidence: [probes_operators.json](audits/ultradeep-2026-10-25/probes_operators.json).

## Additional improvements and unresolved checks

Validation-only finalization should publish an EMA validation score or an explicit non-evaluation status when EMA is enabled. The ordinary finalizer has that path; the validation-only callback does not. With evaluation cadence beyond the stopping point, an ablation can accumulate and save the shadow without ever measuring it. Raw-weight selection remains internally defined, so this is an evaluation-coverage improvement rather than evidence that EMA should replace the selection policy.

Sweep validation and execution should use the same effective cell constructor. Validation merges the baseline and overrides directly, while execution also merges run knobs and repairs an evaluation stride that exceeds a shortened context. The discrepancy can reject an arm that the runner was designed to accept. The currently selected frame-capacity arms do not demonstrate this mismatch.

Paper fallback selection should preserve the posthoc NLL-versus-evaluator cross-check qualification. A pass can retain `status='ok'` and `cross_check.ok=False`, while paper assembly admits it by status, split, and finite score. No ordinary replay mismatch was reproduced here; this is a missing qualification path, not a claim that current paper scores are wrong.

Local-learner results should retain trained parameters, effective configuration, and Monte Carlo provenance. The field `pf_subset_exact_bits` describes a finite-particle estimate. Its name and output metadata should reflect that, and close filter/PF comparisons need repeat estimates or particle-count convergence evidence. Resumed stack grouping can alter its random draws; per-run RNG streams would make those comparisons easier. This does not by itself invalidate existing reported scores.

The frame-RoPE cache failed a direct private-helper-to-matmul mode-transition check, but a full tiny-model inference-to-training transition passed. The compact path builds an ordinary stacked tensor before its differentiable products. It is therefore a cache-policy residual, not an additional production defect. Other optional local-basis caches are also listed as unexecuted residual checks. The reports do not promote those suspicions into findings.

The daily log already records earlier inactive-setting test failures involving `decode_covariance='encoded'` and a covariance-floor mark. Those entries were read for continuity, not rerun or counted as new executed failures. F12 identifies a concrete singleton branch that loses mode-specific marks; further remediation should retain the distinction between an inert-setting report and a wrong forward calculation.

## Coverage, retained theory boundaries, and handoff

The live Research wiki and current manuscripts were consulted before assessing the gauge/VFE mechanisms. Relevant continuity sources included `Attention/GL(K)_attention_v2.tex`, `GL(K)_supplementary_v2.tex`, `minimal_agent_model.tex`, `edge_latent_links.tex`, the projected predictive/gradient and natural-gradient wiki pages, and the prior local generative-memory and local-learner investigations. Those sources contain work at different maturity levels; the implementation findings rely on source traces and executed evidence rather than manuscript authority.

The source implements the intended local posterior, moment-projection, and finite-sweep distinctions. This audit did not establish a new structural gauge-equivariance defect or claim that the entire stack is the exact posterior of one normalized joint. It did not mistake reference content links for flat vertex-frame transport, a finite mean-field sweep for an exact joint calculation, a default-off instrument for dead code, or an intentional frame-bound choice for a broken toggle. The existing pure-route construction remains reachable at the configuration/source level. No exhaustive mathematical certification of all representations, numerical branches, or trained behavior follows from that observation.

Detailed semantic coverage and limits are in the ten lane documents under [the audit folder](audits/ultradeep-2026-10-25/brief.md). Evaluation/data source reading found cache-only real-corpus loading without a synthetic substitution, distinct sample-versus-evaluation protocols, and existing target masks and checkpoint compatibility checks. Training source reading found accepted-update scheduler accounting, weighted accumulation, RNG rewind before numerical retries, and raw-versus-selected model handling. These scoped negative results do not replace end-to-end execution of every path. Semantic batteries, higher-rank representation construction, all figure renderers, every optional model combination, and compiled GPU kernels remain incompletely exercised.

The smallest useful remediation begins with F01/F02 and float32 regressions, then the tied-bank accounting/probe consumers, test dtype isolation, and resume/selection provenance. Optional-path fixes can follow in one batch with their tiny reproductions. Performance work should begin with the reusable support plan and exact identity/diagonal structure, then obtain GPU measurements before claiming speed or memory gains. This is a proposed order, not authorization to alter the live settings or execute experiments.

The audit folder retains every probe script and receipt, the raw/resolved configuration, source inventory, baseline hashes, and [final workspace preservation check](audits/ultradeep-2026-10-25/workspace-verification.json). Some first probe attempts were rejected by configuration validation or had output-serialization mistakes; their corrections were confined to audit scripts and are disclosed in the corresponding records. No failed attempt is represented as a successful model test. The source checksum comparison and Git status verify the original WIP was preserved. The report is local and uncommitted; no remote synchronization claim is made.
