# Changes — October 5, 2026

## Removal of both head mixers (PR #45)

This section was written with PR #45 but not committed with it, because `docs/` is ignored by Git and the file was not force-added; it is restored here unchanged in substance.

The Schur-commutant head mixer (`use_head_mixer`, `vfe3/model/head_mixer.py`) and the PriorBank head-evidence mixer (`use_priorbank_head_evidence_mixer`, `vfe3/model/head_evidence.py`) were removed at the user's request, together with their learning rates `m_head_mixer_lr` and `m_head_evidence_lr`. Both were default-off. The head mixer no longer improved performance, and its mean action is a constrained special case of what the learned relational maps already do: `T` has shape (H, d, H d) and `O` has shape (H, H d, d), so every content chart reads from and writes into every head, and the exponential chart adds the second-order cross-head terms T_g O_h inside one link. Under the default untied `block_glk` gauge the mixer was not an intertwiner, and its covariance action is largely covered by `predictive_covariance="moment_matched"`, whose update carries cross-head terms through M_h = O~_h T_h. The evidence mixer was a separate per-block KL calibration of the canonical decode; it was removed in the same change because it also showed no gain.

The code that existed only for the mixers went with them. In `vfe3/model/prior_bank.py` the evidence path threaded through every decode kernel as `coord_delta`, `evidence_delta`, `evidence_lhs` and the per-head block certificate `block_ok`; all of these were `None` or all-true when the mixer was off, so the default decode path is unchanged. Removed with them: `_decode_head_evidence_kl_delta`, `_head_evidence_full_marginal_invariants`, `validate_priorbank_head_evidence_contract` and the canonical-decoder identity tables, plus the `log_v` entry of the decode-bank factor cache that only the evidence delta read. In the stack, `vfe_block` and `vfe_stack` lost the `head_mixer` argument and the private `_need_mixer_covariance` / `_need_final_covariance` / `_mean_only_loss` plumbing, which existed only to let the mixer skip its covariance on the final linear loss. `metrics.head_mixer_gauge_residual`, the `val_builder_resid` CSV column (no longer written by any route), the `gauge_residual_drift` figure and its ablation driver, the `head_mixer_drift` and `head_evidence_*` diagnostics, the `lr_head_mixer` / `lr_head_evidence` columns, the head-mixer config validations, and the `head_mixer_compatibility` / `head_mixer_gauge_compatible` properties and their report fields were removed. The ablation gauge-purity summary no longer carries `classifications_by_label` or `contains_independent_head_nonintertwiner`, and the cross-sweep bar label is now `block_mlp=<mode>`.

A serialized config that sets either mixer flag to False, or carries either learning rate, loads with those keys dropped. A config that sets either flag to True is refused as retired, since its forward no longer exists here. Checkpoint parameter names are otherwise unchanged; a mixer-on checkpoint carried `head_mixer.*` or `prior_bank.head_evidence_logits` and is refused at its config.

Launchers: the four fields were removed from `train_vfe3.py`, `ablation.py`, `scaling.py`, `parameter_optimization.py` and the `agent_tooling/` probes. In `ablation.py`, the `relational_no_head_mixer` arm and the `use_head_mixer=True` requirement left the relational attention suite, which is now three arms, and the `head_mixer_off` arm left `component_ablation_forest`, which now holds only its baseline until a component arm is added. `scaling.py` no longer counts mixer parameters. `zzzzz.py` was not edited in the PR; the user's uncommitted copy lost its 12 mixer lines at the local handoff.

Tests: `test_head_mixer.py`, `test_head_mixer_isotypic.py`, `test_head_mixer_per_block.py`, `test_priorbank_head_evidence.py` and `test_final_covariance_20260906.py` (the mixer covariance-omission regressions) were deleted. Tests that only passed a mixer flag lost it; tests that used an evidence variant as a second parametrization now use the unigram prior or no variant; the reporting, semantics and forest tests that used the mixer as their example optional component now use `use_block_mlp`, `use_cg_coupling`, `predictive_covariance="moment_matched"` or a `lambda_beta` arm. `tests/test_head_mixer_removal_20261005.py` pins the serialized-config migration and the rejection of the removed fields. A focused CPU run over the 92 affected test files gave 1,779 passed and 2 skipped, with one failure (`test_norms.py`, whose shared fixture had enabled the mixer) fixed and rerun.

## SO(N) plan, Phase 0: canonical irrep basis, basis fingerprint, Gram certificate, compact-group chart

This implements Phase 0 of `docs/implementation/so-n-mixed-towers-and-frame-tying-plan-2026-10-05.md` (decisions D1 and D2 made the same day). Nothing here changes a `block_glk` result, and an `so_n` config whose irreps are all `l0`/`l1` builds the same generators in either basis.

Equal-head goldens. Before any edit, `tests/data/equal_head_goldens_20261005.pt` was captured at 389413b: for `block_glk` (K=4, two heads) and `so_n` with `[("l1", 2)]` (K=6, two heads) on four projected routes (predictive diagonal and full, gradient diagonal and full closed form), the initial state dict, the `forward_beliefs` mean, covariance and phi, the loss and every parameter gradient, at float32 on one CPU thread. A second capture reproduced it bitwise. `tests/test_son_phase0_20261005.py` asserts `torch.equal` against it, for `so_n` in both bases; the only allowed new state key is `gauge_basis_fingerprint`.

Canonical irrep basis (`vfe3/geometry/irreps.py`). The registry now takes a `basis` argument, `"canonical"` (default) or `"eigh"`. For SO(3) the canonical spin-l block is built in closed form from the angular-momentum ladder in the real spherical-harmonic basis and mapped onto the `so_n` generator basis by exact Frobenius projection onto the standard rotation generators; l=1 is the defining representation itself, so it coincides with the eigh basis. This lifts the rank-6 cap of the tensor-power construction: spins 7 and above, including the l=8 block of the example tower `[("l3", 3), ("l8", 1)]` (K=38), now build in milliseconds. For N != 3 the canonical basis keeps the tensor-power construction but replaces the eigh/SVD/QR steps by a monomial basis of Sym^p and a fixed-order Gram-Schmidt of the traceless projector's columns. The old construction stays reachable as `"eigh"`. Tests check exact skew-symmetry, the Casimir -sum_a rho_l(L_a)^2 = l(l+1) I, ||rho_l(L)||_F^2 = l(l+1)(2l+1)/3 up to l=12, bitwise rebuilds, and that for l = 2, 3, 5 the two bases differ by an orthogonal intertwiner whose space is one-dimensional.

Config (`vfe3/config.py`). New field `irrep_basis: str = "canonical"`, validated for `so_n` and reported inactive for other groups; each label is checked for constructibility at config time, so an eigh tower with l > 6 fails there rather than at model build. `config_from_serialized` inserts `"eigh"` for an `so_n` config saved without the field, because its learned tables live in that basis and cannot be rotated into another in general (a block rotation does not keep a diagonal covariance diagonal). `build_group` forwards the field; `tests/profiles.py` lists it.

Basis fingerprint (`vfe3/geometry/groups.py`, `vfe3/model/model.py`). The `so_n` builder records a sha256 of its float64 generators in a new `GaugeGroup.basis_fingerprint`, and `VFEModel` stores it as the `uint8` buffer `gauge_basis_fingerprint` (so_n only; `block_glk`'s elementary basis is deterministic). `VFEModel.load_state_dict` refuses a checkpoint whose digest differs, and loads a checkpoint without one (every so_n checkpoint saved before today) with a warning that its basis cannot be verified.

CG coupling (`vfe3/geometry/cg.py`, `vfe3/model/cg_coupling.py`). The intertwiner solve, its cache key and `cg_selection` take the basis, so the coupling is built in the group's basis. After a state-dict load, `CGCoupling` re-verifies every loaded `cg_*` buffer against its own rebuilt irreps (C (rho_a ⊗ rho_b)(X) = rho_c(X) C for every generator); a buffer saved in another basis now fails the load instead of silently coupling with the wrong intertwiner. This also covers older so_n+CG checkpoints that carry no fingerprint.

Gram certificate. The `so_n` builder computes the generator Frobenius Gram in float64 and, when it is diagonal with one common weight (verified to 1e-12 relative, which holds for every so(N) tower because the trace form of any representation of a simple algebra is a multiple of the Killing form), certifies `frobenius_gram_diagonal=True` with `frobenius_gram_uniform` = sum over blocks of ||rho_b(L)||_F^2 (492 for the l3³+l8 tower). `embedded_phi_frobenius_norm` then takes the exact diagonal route instead of the dense fallback and its RuntimeWarning.

Compact-group chart (`vfe3/geometry/transport.py`, decision D1). A skew-symmetric group is exempt from the fail-closed transport radius: `compute_transport_operators` and `build_factored_transport` pass `+inf` for it through the new `_group_chart_radius`, and `_resolve_chart_max_norm` now accepts `+inf` (rejecting NaN and non-positive values; the nonfinite-norm check still applies). The radius guards conditioning, and the exponential of a skew matrix is orthogonal at any norm: for the l3³+l6 tower the float32 frame keeps condition number 1.000 at every norm tested, with orthogonality error 1.5e-6 at the old limit. The radius is unchanged for `block_glk`. `tests/test_transport.py` was updated to the new contract (`+inf` accepted, NaN refused; an so_n frame past the radius exponentiates exactly). The optional principal-ball rechart of so_n phi rows described in the plan was not implemented: the plan makes it conditional on trained tables drifting past a rotation angle of pi.

## SO(N) plan, Phase 1: tied mixed irrep towers on both projected routes

This implements Phase 1 of `docs/implementation/so-n-mixed-towers-and-frame-tying-plan-2026-10-05.md`. An `so_n` irrep tower may now assign blocks of different sizes to different heads, one block per head, with one shared SO(N) frame per token; for example SO(3) with `[("l3", 3), ("l8", 1)]`, K=38 and four heads. Equal-head partitions, including every `block_glk` config, keep their stored tensors, their parameter names and their arithmetic: the Phase 0 goldens still pass with `torch.equal`.

Config (`vfe3/config.py`). For `so_n` the `embed_dim % n_heads` check no longer applies, and the equal-block rule is replaced by `n_heads == len(irrep blocks)`, which raises with the block count and dims when they disagree. That rule makes the separate ALiBi head-count check in the `so_n` seam redundant, so it was removed (the model-level check is unchanged). New properties `head_dims` (the block sizes for `so_n`, `[K // H] * H` otherwise) and `head_offsets`; `d_head` raises for a mixed tower and names `head_dims`. The logging-only `tau` property returns the mean of kappa_h sqrt(d_h) for a mixed tower and its old value otherwise.

Operator storage (`vfe3/model/relational_operators.py`). The maps are stored per run of contiguous equal-size heads (`head_runs`). One run stores today's four tensors under today's names with today's initialization draw. Several runs store a `ParameterList` under each name, with state-dict keys `T.0`, `T.1` and so on, run r holding `(n_r, d_r, K)` and `(n_r, K, d_r)` maps initialized exactly as the equal-head block projectors. `comparison_runs` and `content_factor_runs` are the per-run accessors; `comparison_pair` and `content_factors` keep their equal-head contract and refuse a mixed tower. The content-link charts (`chart_receive_runs`) build the K x K row stack of T and column stack of O, which are square whatever the partition, and split the effective receiving map back into runs. `canonical_mean` now returns the flat `(..., N, K)` coordinates. The predictive content sums one contraction per run. The dense moment-matched covariance runs its head-pair terms over pairs of runs, with the spread and the self-coupling c^{hh} = beta^h on the diagonal pairs and the residual cross term summed over runs; the blockwise variant applies only to compact frames, which exist only for equal heads.

Routing score (`vfe3/gradients/relational.py`). This departs from section 2.3 of the plan, which said each run would read only its own diagonal blocks of the frame. That is wrong: every head reads the whole belief through the whole frame, L_h = S_h U^{-1}, and the compact `(..., N, H, d, d)` restack used for equal heads stacks the frame's blocks, not the heads' own blocks. For a mixed tower the scorer therefore passes the dense inverse as one full-width block `(..., N, 1, K, K)`, a layout `projected_moments` and the recovery path already accept, and calls the scorer once per run. The per-run scores concatenate along the head axis in head order. The captured projected covariances are one tensor for equal heads and a list with one tensor per run for a mixed tower; the diagnostics and the numerics counts in `train.py` read both forms. Each scoring call still ends in its own host transfer, so a tower with R runs pays R transfers per call. Merging them into one, as the plan proposed, would need the status and compute phases of `projected_gaussian_kl` and `projected_noisy_query_cost` split apart, and was not done.

Projected-gradient receiver (`vfe3/gradients/full_link.py`). `_source_channel` returns per-run lists through the new `_source_channel_run`, and `build_full_link_context` pools run by run: the ambient law sums sum_{h,j} w R^{-1} over runs, and the channel law sums O_r W_r O_r^T. Head-indexed `lambda_beta` is sliced per run.

Diagnostics and records. `VFEModel.diagnostics` reads the comparison and content maps per run and reports the mean head rank K / H in the two rank columns (d_head for equal heads). `metrics.content_link_head_invariants` and `content_link_spectrum` accept per-run lists and compute the head invariants by slicing the K x K head-transfer matrix (`_head_transfer_full`, `_mixed_head_invariants`); the equal-head path is unchanged. `run_artifacts._relational_artifact_fields` records 2K^2 parameters per map and per-head shape lists for a mixed tower and unchanged values for equal heads. The FLOP proxy in `_cost_model_fields` uses the mean squared block size, which is d_head^2 for equal blocks. `build_optimizer`, `train._parameter_group` and `run_resources.parameter_role` read the per-run lists and classify `T.0`-style names by their attribute. `viz/extract.projected_gauge_equivariance` keeps the `so_n` group draw dense rather than slicing it into equal blocks. The covariance-gap, routing-decomposition, map and intervention analyses in `vfe3/posthoc` report not applicable for a mixed tower.

Transport and temperatures. `_blockwise_matrix_exp` and `_blockwise_group_inverse_certified` now take one batched call per run of equal blocks for an unequal partition, instead of one call (and, for the inverse, one host synchronization) per block; the equal-block path is unchanged. `attention_tau` takes the device for a scalar kappa: with unequal blocks it built the per-head temperatures on the CPU, which by torch's device rules would fail against CUDA scores. Its five callers now pass the device. That failure was inferred from the code and not executed, since no GPU workload may run while the V3_Transformer job is active.

## SO(N) plan, Phase 2: the gauge_tying axis

This implements Phase 2 of `docs/implementation/so-n-mixed-towers-and-frame-tying-plan-2026-10-05.md`. A new config field `gauge_tying` (`None`, `"per_head"` or `"shared"`) resolves at construction to each group's native tying: `"per_head"` for `block_glk` and `"shared"` for `so_n`. A saved config without the key therefore loads with today's behavior, and every existing config builds the same group. `GaugeGroup` gains a `tying` attribute, and `build_group` forwards the field to builders that accept it. The retired name `tied_block_glk` is still refused on load.

Tied `block_glk` (`gauge_tying="shared"`) is the diagonal subgroup {I_H ⊗ g : g ∈ GL(d_head)}. One GL(d_head) element per token acts identically on every head through the generators I_H ⊗ E_ab in row-major order, so n_gen = d_head^2 and the Frobenius Gram is H times the identity. No generator lives on a single head. The per-block metrics (`killing_per_block`, `pullback_per_block`) are therefore refused, along with `pullback_group`, `fisher_group` and the `group_log` retraction, whose closed forms read the chart as per-head blocks. The `group_log` refusal now happens in config for every group other than untied `block_glk`; before, it raised at runtime. The registry certifies the `pullback_per_block` capability only for the per-head tying, through a new `pullback_tying` argument of `register_group`. The tied group carries no `phi_coordinate_layout` and no elementary-block certificate, so it takes the existing dense transport route. The plan's compact tied fast path, which would exponentiate one d x d block per token and expand it over heads, was not implemented: it would need a new coordinate layout threaded through the compact transport, positional and table-lookup paths. The diagonal-rescaling semantics check reports the tied group as broken, because D e^X leaves it unless D repeats across heads.

Untied `so_n` (`gauge_tying="per_head"`) gives every irrep block its own SO(N) element. Block b carries its own copy of rho_b(L_a), supported on that block alone, in block-major order, so n_gen = dim so(N) for each nontrivial block; `l0` blocks carry no generators. The Gram is diagonal, with weight ||rho_b(L)||_F^2 on block b's coordinates, and is certified uniform only when every block has the same spin. The per-block preconditioners are now accepted, since every generator lives on one block. `build_killing_preconditioner_per_block` and `pullback_metric_per_block` skip blocks without generators. CG coupling is refused for untied `so_n`, because an intertwiner commutes only with the diagonal action of one shared element.

Re-keyed sites. `metrics.frame_class_function` dispatches on `skew_symmetric` rather than the group name. The equivariance draw in `viz/extract.py` uses independent per-head blocks only for untied `block_glk`, and draws from the generators otherwise. The scaling record (`_cost_model_fields`) and the pure-path report record `gauge_tying`.

Tests. `tests/test_gauge_tying_20261005.py` (16 tests) covers:
- the native defaults and a saved config without the key;
- the tied basis and its Gram, with frames identical across heads and equal to the explicit d x d exponential;
- the tied refusals, each checked against an untied control config that is accepted;
- the untied basis, with one-block support, the block-major order and its Gram, and frames independent per block;
- the CG refusal, and per-block Killing accepted (including a tower with an `l0` block);
- a train step and the gauge-equivariance residual (below 1e-10) for both new groups on both projected routes;
- the run-record field.

`tests/profiles.py` carries the new key.

## Edge-dependent content links, Level 1 (`content_link_edges`)

This implements Section 2 of `docs/implementation/edge-and-latent-links-plan-2026-10-05.md` (GL(K)_attention_v2 Section 3, `thm:routed_transport`, `lem:lie_lowrank`). Every edge j -> i of the projected predictive readout now carries its own group-valued reference link G_ij = g_i F E_ij with F = e^L the shared exponential-chart link and E_ij = I + A_i Phi_ij B_j^T, built from rank-r factors A_i, B_j in R^{K x r} of the RMS-normalized reference means xi^_i = xi_i / sqrt(mean_k xi_ik^2 + 1e-12) (frame invariant, so G_ij is reference data and the local link U_i G_ij U_j^{-1} is covariant under mu -> g mu, Sigma -> g Sigma g^T, U -> g U). The head edge map is M_h^ij = G_ij Pi_h with Pi_h = R_h T_h and R = T^{-1}, and the message is m~_i = sum_j G_ij Pi(beta_ij) xi_j. Two modes are selected by the new config field `content_link_edges` (default `"off"`). In `"lowrank"` (curved) g_i = I, A_i = reshape(W_A xi^_i), B_j = reshape(W_B xi^_j) and Phi_ij = phi_1(B_j^T A_i), so E_ij = exp(A_i B_j^T) by exp(A B^T) = I + A phi_1(B^T A) B^T; its triangle holonomies vary. In `"pure_gauge"` (flat control) one shared basis A per layer gives g_i = exp(A B_i^T) and Phi_ij = -phi_1(-B_j^T A), so E_ij = g_j^{-1}, G_ij = g_i F g_j^{-1}, and every triangle holonomy G_ik^{-1} G_ij G_jk = g_k F g_k^{-1} is conjugate to F. The rank is `content_link_edge_rank` (default 4). W_A starts at N(0, K^{-2}) (columns of A_i of expected unit norm), A at orthonormal columns, both drawn from the layer's seeded generator after every existing initialization, and W_B at zero, so both modes start exactly at the exponential chart. With the edges off no edge parameter or buffer exists and every existing path, state-dict key and number is unchanged.

The edge algebra lives in the new module `vfe3/model/edge_links.py` (pure functions). The mean is m~_i = g_i O'(z_i + T A_i y_i) with y_i = sum_j Phi_ij c_ij, c_ij = sum_h beta_ij^h p_j^h, p_j^h = (B~_j)_h^T T_h xi_j and B~_j = T^{-T} B_j; pure gauge needs no per-edge matrix function. The moment-matched covariance keeps the kernel of Theorem thm:probabilistic_status (2) with M_h -> M_h^ij: C_i^att = g_i [F(P^_i + sum_h R_h Sigma~_i^h R_h^T)F^T + A^_i X^_i^T + X^_i A^_i^T + A^_i Y_i A^_i^T] g_i^T + r[C_i + cross_i + cross_i^T] + Q~_i, with A^_i = F A_i, X^_i = sum_g O'_g Xi_i^{gT}, Xi_i^g = sum_j Phi_ij sum_h c_ij^{hg} (B~_j)_h^T s_j^{hg} + sum_j beta_ij^g Phi_ij p_j^g v_j^{gT} - q_i^g z_i^{gT}, q_i^g = sum_j beta_ij^g Phi_ij p_j^g, Y_i = sum_j Phi_ij [sum_{hg} c_ij^{hg} (B~_j)_h^T s_j^{hg} (B~_j)_g] Phi_ij^T + sum_h [sum_j beta_ij^h (Phi_ij p_j^h)(Phi_ij p_j^h)^T - q_i^h q_i^{hT}], and cross_i = g_i [sum_h beta_ii^h O'_h T_h C_i + A^_i Phi_ii sum_h beta_ii^h (B~_i)_h^T T_h C_i]. The spread may use the token-0-shifted values (it is shift invariant), but p_j^h is formed from the unshifted values, as the plan requires. Both covariance bodies are extended. The blockwise body (diagonal beliefs on block frames) adds only the diagonal blocks of the correction and of the residual cross term; under `"pure_gauge"` it applies the full outer g_i through (g In g^T)_ll = In_ll + A^(l) phi_i (B_i^T In)_{:,l} + transpose + A^(l) phi_i (B_i^T In B_i) phi_i^T A^(l)T, with the r x K rows B_i^T In formed through B_i^T O'_h and the head-pair pooled covariance, so no dense K x K intermediate appears and pure gauge stays on the blockwise route (three contractions of B N H^2 r d^2 multiply-adds each, about 9.1e8 multiply-adds or 1.8 GFLOP per layer, about 2% of the 97 GFLOP blockwise body at the launcher widths). Pairs with zero routing weight in every head (the causal future) have their phi_1 argument zeroed before the matrix function (lowrank) or their sender coefficient replaced by zero (pure gauge), so a large unused argument cannot overflow into inf * 0. The edge context (float64 chart stacks T, R = T^{-1}, O', F = O'T from one inversion through the new `chart_stacks`, the factors, B~, p and every Phi_ij) is computed once per layer in `relational_predictive_readout` and shared by the mean, the covariance and the diagnostics, with autocast off, IEEE fp32 GEMMs and the readout's compute dtype (float64 under an escalated frame). It is an input of the checkpointed covariance region, so `predictive_covariance_checkpoint` stays bit-identical in values and gradients. `_phi1` now accepts leading batch axes (bit-identical on a single matrix), and `chart_receive_runs` reads `chart_stacks` (the same operations).

Refusals and scope. Edge links require `content_link_chart="exponential"`, `attention_mode="projected_predictive"` and equal heads; `VFE3Config.__post_init__` and the `RelationalOperators` constructor raise a `ValueError` for any other chart, for `projected_gradient`, for a mixed `so_n` tower and for a rank outside [1, embed_dim] (the rank is range-checked only when the edges are on, since tiny test configs use embed_dim 2 and 3), and `inactive_fields()` reports `content_link_edge_rank` when the edges are off. They run with dense and block-diagonal frames, both families, residual on or off, covariance passthrough or moment matched, and the covariance checkpoint.

Wiring. `vfe3/model/model.py` passes both fields to every layer. In `vfe3/train.py` the edge parameters join the relational content group (`m_relational_content_lr`, weight decay 0, aux role `relational_content`), and `_parameter_group` maps `edge_*` under `relational_operators` to `relational_content`; `vfe3/run_resources.py` maps them to `context_processing / relational_content`; the run record (`_relational_artifact_fields`) counts them in the content parameters and adds `content_link_edges` and `content_link_edge_rank` only for an edge-enabled config. ## Latent receiver factors, Level 2 (`content_link_latent`, `content_link_loop_weight`)

This implements Section 3 of `docs/implementation/edge-and-latent-links-plan-2026-10-05.md` (GL(K)_supplementary_v2 Section S6, `sec:latent_links`, `prop:lie_field_equation`). With `content_link_edges="lowrank"` and the new `content_link_latent=True`, the receiver factor A_i of every edge link G_ij = e^L exp(A_i B_j^T) is no longer the amortized A_i^0 = a(xi^_i) but its per-context MAP estimate under the prior A_i ~ N(A_i^0, sigma_L^2 I). Only the receiver factor is latent: a sender factor B_j is shared by every receiver i >= j, so inferring it would carry later positions into earlier ones, while each receiver's problem reads its own A_i and the sources its routing reaches, so it is causal and independent of the other receivers. Profiling the receiver's next-layer law N(r xi_i + m~_i, c_i I), c_i = tr(C_i)/K, out of the S6 free energy leaves the expected transport energy E_i(A_i) = tr C_i^att(A_i) / (2 c_i), the reference-coordinate trace of the Section 2.3 moment-matched covariance without the floor, and the per-receiver energy is F_i(A_i) = E_i(A_i) + ||A_i - A_i^0||_F^2 / (2 sigma_L^2) + lambda_W Loop_i(A_i). The trace is computed directly from the Level 1 algebra, tr C_i^att = const_i + 2 <A^_i, X^_i> + <Y_i, A^_i^T A^_i> + 2 r tr(Phi_ii kappa_i A^_i), with A^_i = F A_i, X^_i and Y_i from `edge_covariance_factors` at Phi_ij = phi_1(B_j^T A_i), kappa_i = sum_h beta_ii^h (B~_i)_h^T T_h C_i, and const_i = sum_{h,g} <P_i^{hg}, O'_h^T O'_g> + r [tr C_i + 2 sum_h beta_ii^h tr(O'_h T_h C_i)] evaluated from the scalars <s_j^{hg}, O'_h^T O'_g> without forming the pooled head-pair covariance. No local covariance is materialized, and diagonal beliefs on block frames use only the diagonal reference blocks. The energy is computed whatever `predictive_covariance` is, since it is part of the link inference. The identity is pinned by a test against the trace of the Level 1 dense covariance body with the floor removed, at a random A != A^0: the worst relative error is 5.9e-16 over both families, both frame layouts and residual on and off.

Inference runs `content_link_latent_steps` = T damped fixed-point steps of the stationarity condition, A_i^(t) = (1 - rho) A_i^(t-1) + rho (A_i^0 - sigma_L^2 grad_{A_i}[E_i + lambda_W Loop_i](A_i^(t-1))), A_i^(0) = A_i^0, the unit natural-gradient step in the Fisher metric of the prior. The gradient of the summed (decoupled) energies comes from `torch.autograd.grad`. With gradients enabled it uses `create_graph=True`, so every outer parameter (comparison and content maps, W_A, W_B, frames, tables) trains through the unrolled steps. Under `torch.no_grad` the steps run under `torch.enable_grad()` from a detached A^(0) with `create_graph=False`, and `torch.inference_mode` is refused with a `RuntimeError`, since the energy must be differentiated. The final message, covariance and diagnostics use A^(T), with Phi_ij recomputed (masked before phi_1 as in Level 1). sigma_L -> 0 is the static limit, the Level 1 model.

The optional loop prior adds lambda_W Loop_i with Loop_i = sum_{(j,k)} pibar_ij pibar_jk Psi(W_ijk), Psi(W) = ||W - I||_F^2 / 2, over the loops W_ijk = (G_ik^{l+1} G_kk^l)^{-1} G_ij^{l+1} G_jk^l = (E_kk^l)^{-1} e^{-L_l} (E_ik^{l+1})^{-1} E_ij^{l+1} e^{L_l} E_jk^l with i - w <= k < j <= i (w = `content_link_loop_window`; w = 1 keeps only the time-like loop k = i - 1, j = i; `None` keeps every loop). Every loop is the identity for the static shared-generator model, layer 0 has none, and the weights come from the head-averaged routing prior (the head mean of `softmax(log_prior)` rows, causal uniform without a prior). The implementation does not multiply K x K matrices: every factor is a rank-r update of the identity, and F_l cancels between (E_kk^l)^{-1} F_l^{-1} and F_l E_jk^l, so W_ijk - I = V_jk b_k^T + P_ik Q_ijk^T exactly, with V_jk = a_j phi_jk - a_k psi_kk (I + b_k^T a_j phi_jk), P_ik = (E_kk^l)^{-1} F_l^{-1} A_i and Q_ijk^T = Z^T F_l + Z^T F_l a_j phi_jk b_k^T, Z^T F_l = (I - Psi_ik B_k^T A_i) Phi_ij B_j^T F_l - Psi_ik B_k^T F_l (Phi_ij = phi_1(B_j^T A_i), Psi_ik = phi_1(-B_k^T A_i), phi_jk = phi_1(b_k^T a_j), psi_kk = phi_1(-b_k^T a_k) for layer l's factors a, b). The squared norm then comes from r x r Gram traces. That costs O(K r^2) per loop after O(N K^2 r) per layer, instead of O(K^3) per loop. Loops of zero prior weight are dropped before any factor is formed. They contribute nothing, and with a hard-masked routing prior (for example `causal_windowed` narrower than the loop window) evaluating them let a far sender's phi_1 overflow become 0 * inf = NaN in a receiver whose weighted loops were finite (found in the integration review; fixed and tested). Loops are evaluated in float64, because e^{-L} can be very large for trained generators and the loop is a near-cancellation of its two paths. Layer l's state (F_l, e^{-L_l} = matrix_exp(-O T) in float64, its inferred A^l and its B^l) is threaded to layer l+1 through one `link_state` dict that `vfe_stack` creates only when some layer has a positive loop weight and passes through `vfe_block`, `e_step`, `e_step_iteration` and `relational_predictive_readout` to `RelationalOperators.edge_context`. The readout reads `"previous"` and writes `"current"`, and the stack promotes `"current"` to `"previous"` after each block. With the loop weight at 0 no dict exists and no call signature on the default path receives a new argument. The previous layer's links are fixed during layer l+1's inner problem, but they are not detached, so the outer gradient also reaches layer l through the loop term. The prior weights are not detached either, which matters only for a learnable T5 bias.

Stability. The plan's unit natural-gradient step is stable only while sigma_L^2 times the curvature of E_i + lambda_W Loop_i stays below about one. E_i is the predictive variance in units of the receiver's own mean variance, and its gradient grows like phi_1 of B_j^T A_i, so the step can overshoot by orders of magnitude. In the tiny float64 cases (rho = 1, 100 steps), one receiver with E_i of about 5e3 diverged to NaN at every sigma_L >= 0.02. Cases with E_i below about 20 reached a fixed point to 1e-17 at sigma_L = 0.1. In a three-layer tiny model with W_B ~ N(0, 0.09), sigma_L = 0.3 with lambda_W = 2 diverged. sigma_L = 0.2 with lambda_W = 2 raised the energy without diverging, and sigma_L <= 0.2 with lambda_W <= 0.5 lowered it. Damping helps against oscillatory overshoot: near a fixed point whose Hessian is positive definite with largest eigenvalue h, the damped map contracts for rho < 2 / (1 + sigma_L^2 h). The first step still moves A^0 by rho sigma_L^2 grad E(A^0), though, so a large initial gradient overshoots unless rho is small. The integration review reproduced this at the tiny shape (K = 4, N = 4, r = 2, three layers, W_B ~ N(0, 0.09), sigma_L = 0.2, two steps, window 2): lambda_W = 0.5 and 1 lower the energy at every layer with loss 1.95, while lambda_W = 2 gives a loss of 3.55e16, `relational_latent_energy_final` = [6.45, 75, NaN] against `energy_initial` = [6.56, 19.4, 23.1], and a receiver shift of 9.87 at layer 2. That loss is finite, so the nonfinite-loss gate of `vfe3/train.py` does not skip the update, and the latent diagnostics are captured only at validation. The independent reference iteration diverges identically (same NaN at the same step), so this is a property of the plan's unit step, not an implementation error; in that regime the rank-r trace form and the explicit-matrix form also lose all significant digits. No trust region, backtracking or step normalization was added, because the plan fixes the iteration and the pure path must stay as specified; an opt-in per-receiver guard (keep the previous iterate where the energy is nonfinite or rose, and count the guarded receivers in the training metrics) is the natural addition if the user wants one. The default sigma_L = 0.1 should be checked against `val_relational_latent_energy_final` (which rises above `energy_initial` when the step overshoots) and `val_relational_latent_receiver_shift` before long runs.

All arms need `attention_mode="projected_predictive"`, `content_link_chart="exponential"` and equal heads, which the current launcher already has. The comparison has three Level 1 arms and two Level 2 arms. (1) The exponential-chart baseline: `content_link_edges="off"` (the default).
